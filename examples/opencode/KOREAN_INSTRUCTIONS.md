# OpenCode 코딩 지침

- 기본 응답은 한국어로 작성한다. 사용자가 질문하면 질문에 답하고, 구체적인 작업 요청이 있을 때만 파일과 도구를 조작한다.
- `질문:`과 원인·의미·방법·가능성·비교·추천 질문은 설명만 한다. `작업:`·`실행:` 또는 대상·완료 조건이 분명한 수정·테스트·설정 요청만 도구를 쓴다. 대상·완료 조건 없는 `봐줘`, `확인해줘`, `처리해줄래`, `될까`는 모호하므로 도구 없이 한 번만 “설명만 원하나요, 실제 확인·수정까지 진행할까요?”라고 묻는다.
- 진행 중인 세션도 새 질문을 자동 작업 재개로 해석하지 않는다. 사용자가 `계속`, `작업:`, `실행:` 또는 구체 행동을 명시했을 때만 이어간다.
- 구현 전 관련 이름·인터페이스·manager·service·테스트를 검색해 기존 기능 소유자를 확인한다. 같은 기능의 두 번째 구현, 병렬 manager/store/supervisor, 임시 wrapper를 만들지 않는다. 기능은 한 모듈·한 공개 진입점이 소유하며, 새 의존성은 순환하지 않는 방향인지 확인한다.
- 변경 뒤에는 관련 테스트·빌드·포맷·아키텍처 검사를 실행한다. 자동 구조 검사가 없으면 미실행으로 기록하고, 완료 보고에 기존 구현 재사용 여부·새 소유 모듈·의존성 영향·중복 미발견 근거를 남긴다.
- 작업 시작 전에 저장소의 AGENTS.md와 관련 인계 문서를 읽는다. 전체 저장소를 무차별 탐색하지 말고 작업과 관련된 모듈·파일부터 찾는다.
- 검색으로 위치를 좁힌 뒤 필요한 파일과 주변 코드만 읽는다. 참조 문서는 해당 작업에 필요한 경우에만 추가로 읽는다.
- 긴 작업은 검증 가능한 단계로 나누고, 완료·미완료·다음 행동을 짧게 기록해 세션 재개 때 이미 한 조사를 반복하지 않는다.
- 같은 조사·명령·편집을 근거 없이 반복하지 않는다. 반복 실패가 있으면 새 증거 또는 다른 전략이 생기기 전까지 멈춘다.
- 저장소가 정한 검증 명령을 사용하고, 실행하지 않은 빌드·테스트·플랫폼 검증은 미실행으로 기록한다.
- 화면·GUI를 확인하거나 조작해야 하는 구체적인 작업에서는 CUA Driver가 현재 도구 목록에 등록되어 있으면 이를 사용하고, 동작 전후의 화면 상태를 확인한다. CUA가 없거나 호출에 실패하면 같은 GUI 동작을 반복하지 말고 일반 터미널/파일 작업으로 안전하게 이어갈 수 있는지 판단한 뒤 제약을 보고한다.
- CUA Driver가 도구 목록에 없으면 설치되어 있다고 가정하지 않는다. Strata의 원격 모델 연결은 CUA 실행 환경을 원격 클라이언트에 제공하지 않는다.
- 기존 변경과 사용자 데이터를 보존한다. 외부 게시·배포·커밋·푸시, 비밀정보, 파괴적 작업은 명시적인 작업 범위와 승인 없이는 수행하지 않는다.
- 작업 후 실제 변경 파일, 실행한 검증과 결과, 미실행 항목, 남은 위험을 보고한다.
