# 실행·컨텍스트·작업 복구

## 현재 상태와 중복 방지

- 채팅 기록이 없는 새 세션도 현재 요청의 대상·완료 조건을 기준으로 AGENTS.md, 관련 README·설계 정본·코드·diff만 읽는다. 과거 대화·승인·검증 성공을 추정하지 않는다. Git이 없으면 파일 상태로 확인한다. 인계 문서는 참고 근거이고 현재 실행 허가가 아니다. 목표를 알 수 없는 `계속해`만 받으면 대상·목표를 한 번 묻고, 판단할 근거가 있으면 과거 채팅을 요구하지 않는다.
- 검색으로 관련 경로·심볼을 좁혀 필요한 구간만 읽는다. 전체 저장소·종속성·생성물·로그를 넣지 않는다. 결과가 잘리면 검색 범위를 좁힌다. 유효한 읽기 결과는 재사용하고 수정·외부 변경·압축 후 불확실성·patch 불일치가 있는 구간만 다시 확인한다.
- 기존 설계 정본·호출부·테스트로 기능 소유자를 확인한다. 같은 기능의 두 번째 구현·병렬 manager/store/supervisor·반복 설계 문서를 만들지 않는다. 반복 요청은 새 요구와 미완료 부분만 처리한다. 필요한 플랫폼 어댑터를 이름이나 코드 유사성만으로 합치거나 삭제하지 않는다. 순환 의존성을 피하고 실제 공통 요구만 추출한다. 이미 다른 작업자가 맡은 변경을 확인하며 같은 수정을 두 작업자에게 동시에 맡기지 않는다.
- 작은 수정은 최소 변경으로 끝낸다. 불필요한 계획·인계 파일·추상화·파일 분할·재포맷을 만들지 않는다. 긴 구현은 기존 모듈 경계를 유지한 변경 묶음으로 진행한다. 16000자는 한 write 호출의 크기이며 최종 파일 크기나 모듈 분할 기준이 아니다. 입력·출력 한도를 채우려 하지 않으며 최종 답변에 코드·계획·로그 전체를 반복하지 않는다. 사용자가 고른 추론 수준은 임의 변경하지 않는다.
- 검증은 영향받는 검사부터 하고 공유 코드·API·의존성·통합 영향이 있으면 넓힌다. 저장마다 동일한 전체 빌드를 반복하지 않는다. 성공한 검증은 관련 소스·설정·의존성·환경이 같을 때만 재사용한다. 필요한 검증이 없거나 실행 불가이면 미실행과 한계를 보고한다. 같은 원인의 무진전 시도는 새 증거 없이 반복하지 않으며 두 번을 넘기지 않는다.

## 유한 실행·취소·완료

- 셸은 비대화형·유한 timeout·종료 코드·출력 로그를 사용한다. 짧은 조회는 보통 15~30초, 일반 명령은 120초를 출발점으로 하고 긴 빌드·관측에는 예상 시간과 여유를 명시한다. ACP timeout 0은 120000ms로 보정된다. 고정 sleep 대신 필요한 준비 조건을 기한 안에서 확인하고 충족 즉시 진행한다. 조용한 정상 빌드를 중복 실행하거나 임의 중단하지 않는다.
- Windows ACP는 UTF-8 임시 스크립트와 설치된 PowerShell bootstrap을 사용한다. 직접 실행은 scripts/run_bounded_command.ps1의 -CommandFile을 활용한다. WSL은 배포판·Linux 경로·실행 파일을 명시하고 Windows/WSL 패키지 위치를 섞지 않는다. Linux/macOS는 run_bounded_command.sh를 쓰며 GNU timeout(gtimeout)이 없으면 지원되는 유한 실행기를 사용한다.
- 관리자 승격·UAC·인증을 무제한 기다리거나 우회하지 않는다. Start-Process -Verb RunAs/runas/sudo/gsudo와 보안 데스크톱 승인은 금지한다. 권한이 필요하면 BLOCKED_UAC와 필요한 단일 관리자 명령·이유를 기록한다. 일반 확인은 제한 시간 안의 실제 완료 증거로만 진행하며 없으면 WAITING_FOR_USER_CONFIRMATION으로 기록한다. 차단 단계·의존 작업을 보류하고 이미 허가된 독립 작업만 진행한 뒤 미완료 조건을 보고한다. 늦은 승인은 새 `승인 완료, 계속` 요청에서 소유 대상 상태를 확인한다. 승인 대기·같은 실행 재시도는 하지 않는다.
- Rider/Hermes ACP에서는 필수 셸·하위 작업을 현재 요청 안에서 기다린다. shell/subagent background는 사용하지 않고 충분한 유한 timeout을 지정한다(300초 관측 예: 420000ms). 필수 검증을 남긴 채 나중에 보고하겠다고 응답을 끝내지 않는다. 이미 실행한 작업은 중복 시작하지 말고 소유 PID·로그·도구 완료 규약으로 결과를 확인한다. 결과가 없으면 검증 미완료로 보고한다.
- 명시적으로 요청한 상시 서버·watcher만 별도 프로세스로 실행하고 PID·로그·health로 시작을 확인한다. 최종 보고에 계속 실행 중임을 밝힌다. 단순 모델 생성의 Strata done은 전체 업무 완료가 아니다.
- 완료는 종료 상태다. 수락 조건을 충족하면 필요한 자신 소유 CUA session 정리 후 최종 보고하고 추가 조사·재검증·자동 작업을 시작하지 않는다. 단계 예산은 조기 완료를 금지하는 목표가 아니다. 기본 200단계(사용자 지정값 우선) 안에서 남은 조건을 진행하고, 한계 전에 완료·미완료·검증·다음 행동을 남긴다. 무진전 중단·취소 규칙은 예산과 별개이며 단계 한계나 오류를 성공으로 보고하지 않는다.
- 사용자 중지는 취소이며 복구 재시도·추가 검증·늦은 알림의 자동 재개로 바꾸지 않는다. 이미 저장한 파일을 자동 롤백하지 않는다. 파일 저장·설치·MCP 입력 등 실행된 부작용은 취소만으로 되돌려지지 않는다. 새 요청 없이 후속 작업을 계속하지 않는다.

## MCP 선택·오류·압축

- 일반 코드 작업은 기본 파일 도구, GUI는 cua-driver, 바이너리·패키지 역공학은 rea_analysis를 필요할 때만 사용한다. 세부 재구현은 REA 분석 에이전트, 엔진별 작업은 프로젝트의 해당 지침을 따른다. GUI 입력 제한을 셸로 우회하지 않는다. 클라이언트 CUA의 화면을 원격 Strata 서버 화면으로 혼동하지 않는다.
- 현재 도구 스키마를 사용하고 매 단계마다 모든 서버의 목록과 사용법을 다시 조회하지 않는다. 부재·스키마 변경·연결 복구 때 필요한 목록만 갱신한다. 유효한 분석/창 ID·결과는 재사용하되 대상 변경·재시작·만료·불일치 때 갱신한다. 독립 읽기만 묶고 의존하는 쓰기·GUI 입력은 순서대로 한다.
- MCP의 isError·오류 코드·실제 결과를 확인한다. 전송 성공은 동작 성공이 아니다. 일시적 연결 오류는 기존의 제한된 재시도를 따르며 별도 루프를 만들지 않는다. 인증·권한·미지원·지속 장애는 반복하지 말고 보존한 작업과 필요한 조치를 보고한다. 서버 재설치·재시작을 반복하지 않는다.
- 잘린 JSON·도구 인자는 실행 여부를 확인해 작은 올바른 호출로 고친다. timeout·연결 끊김은 미실행 증거가 아니므로 결과 파일·diff·소유 프로세스를 확인한다. 클릭·쓰기·설치 등은 실제 상태 확인 없이 재전송하지 않는다. 필요한 재실행을 명령 문자열 중복만으로 막지도 않는다.
- 압축은 현재 요청의 종료가 아니다. 필수 영문 제목과 한국어 본문으로 최신 요청·금지 사항·설계/구현 소유자·관련 경로/심볼·완료/미완료·검증 근거·차단·다음 행동을 하나의 최신 체크포인트에 통합한다. 과거 요약·전체 코드·로그·해결된 오류 경과를 누적하지 않는다. 미완성 파일의 저장된 범위와 남은 범위, 불확실한 부작용과 소유 프로세스는 보존한다.
- 압축·재개 후에는 관련 현재 구간·diff와 남은 조건을 대조한다. 요약보다 실제 상태를 우선하며 완료한 일을 재활성화하지 않는다. 압축만으로 유효한 검증을 무효화하거나 전체 저장소·검사를 처음부터 반복하지 않는다. 기존 인계 문서를 필요할 때만 갱신하고 새 병렬 상태 저장소를 만들지 않는다.
