# 장기 작업 복구

- 재부팅·세션 재개·압축 후에는 현재 Git 상태와 diff, 인계 문서, 관련 프로세스를 확인하고 남은 작업부터 계속한다. 이미 충족한 수정은 재구현하지 않는다.
- 검색으로 파일과 관련 모듈을 좁힌 뒤 필요한 구간만 읽는다. 전체 저장소·로그·생성물·종속성을 컨텍스트에 넣지 않는다. 작은 독립 읽기는 묶고, 결과에 의존하는 수정은 순서대로 수행한다.
- 같은 원인의 무진전 시도는 두 번을 넘기지 않는다. 새로운 증거나 수정 없이 같은 테스트·명령을 반복하지 않는다.
- UAC 보안 데스크톱과 관리자 자격 증명 창은 CUA나 셸 도구로 승인·관찰하지 않는다. `Start-Process -Verb RunAs`, `runas`, `sudo`, `gsudo`를 호출하지 않는다. 권한 거부 또는 UAC가 필요하다는 신호를 받으면 `BLOCKED_UAC`로 기록하고 필요한 단일 관리자 명령·이유를 사용자에게 제시한 뒤 현재 작업을 끝낸다. 승인 대기, 폴링, 같은 명령 재시도, 권한 우회는 금지한다. 사용자가 실행 결과를 준 새 요청에서만 상태를 다시 읽는다.
- 빌드·테스트는 비대화형, 제한 시간, 별도 출력 로그로 실행하고 조용하다고 중복 실행하지 않는다. 서버·watcher는 별도로 시작하고 상태를 확인한다.
- Strata의 `done`은 한 번의 모델 생성 종료이며 전체 작업 완료가 아니다. OpenCode의 도구 실행 결과와 실제 변경·검증을 확인한다.
- 60단계 제한은 한 작업 구간의 경계다. 그 전에 완료·미완료·검증·다음 행동을 인계 문서에 남기고, 최종 답변에는 이를 한국어로 요약한다. 실행하지 않은 검증이나 중단한 작업은 성공이라고 하지 않는다.
- 완료는 종료 상태다. 매 도구 호출 전 아직 충족되지 않은 사용자 수락 조건 하나를 확인한다. 모두 충족됐으면 필요한 CUA session 정리를 끝낸 뒤 즉시 최종 한국어 답변을 보내고, 추가 조사·도구 호출·후속 작업·재검증을 시작하지 않는다. 새 사용자 요청만 새 작업을 연다.
