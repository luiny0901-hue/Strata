## 현재 상태와 중복 방지

- 채팅 기록이 없는 새 세션도 현재 요청의 대상·완료 조건을 기준으로 AGENTS.md, 관련 README·설계 정본·코드·diff만 읽는다. 과거 대화·승인·검증 성공을 추정하지 않는다. Git이 없으면 파일 상태로 확인한다. 인계 문서는 참고 근거이고 현재 실행 허가가 아니다. 목표를 알 수 없는 `계속해`만 받으면 대상·목표를 한 번 묻고, 판단할 근거가 있으면 과거 채팅을 요구하지 않는다.
- 검색으로 관련 경로·심볼을 좁혀 필요한 구간만 읽는다. 큰 파일은 해당 심볼·줄 범위부터 읽고 호출부·계약이 필요할 때만 넓힌다. 전체 저장소·종속성·생성물·로그를 넣지 않는다. 결과가 잘리면 검색 범위를 좁힌다. 유효한 읽기 결과는 재사용하고 수정·외부 변경·압축 후 불확실성·patch 불일치가 있는 구간만 다시 확인한다. 일부만 추릴 때 관련 호출부·제약·최신 수정 요청을 함께 보존하며 단순 키워드 필터로 나머지를 무조건 버리지 않는다.
- 기존 설계 정본·호출부·테스트로 기능 소유자를 확인한다. 같은 기능의 두 번째 구현·병렬 manager/store/supervisor·반복 설계 문서를 만들지 않는다. 반복 요청은 새 요구와 미완료 부분만 처리한다. 필요한 플랫폼 어댑터를 이름이나 코드 유사성만으로 합치거나 삭제하지 않는다. 순환 의존성을 피하고 실제 공통 요구만 추출한다. 이미 다른 작업자가 맡은 변경을 확인하며 같은 수정을 두 작업자에게 동시에 맡기지 않는다.
- 상태·불변 조건·한도·검증 규칙은 기존 소유 모듈 하나에서 관리한다. 단순히 코드 모양이 비슷하다는 이유로 서로 다른 정책을 강제 공통화하지 않는다. 추상화·새 계층·의존성은 실제로 공유할 계약이나 독립적인 변경 이유가 있을 때만 추가한다. 기존 경로를 대체하면 호출부·설정·데이터 호환성을 확인하고 사용하지 않는 중복 경로만 제거한다. 작은 수정 때문에 전체 구조를 재설계하거나 별도 설계 정본을 만들지 않는다.
- 작은 수정은 최소 변경으로 끝낸다. 기존 파일의 국소 변경은 edit/patch를 우선하고 일치하는 대상이 하나인지 확인한다. 새 파일·실제로 전체를 바꾸는 경우에만 write를 사용하며, patch 불일치나 외부 변경이면 해당 구간을 다시 읽고 수정한다. 불필요한 계획·인계 파일·추상화·파일 분할·재포맷을 만들지 않는다. 긴 구현은 기존 모듈 경계를 유지한 변경 묶음으로 진행한다. 16000자는 한 write 호출의 크기이며 최종 파일 크기나 모듈 분할 기준이 아니다. 입력·출력 한도를 채우려 하지 않으며 최종 답변에 코드·계획·로그 전체를 반복하지 않는다. 사용자가 고른 추론 수준은 임의 변경하지 않는다.
- 구현이 쉽다는 이유로 예외 삼키기·성공처럼 보이는 임시 반환·정상 경로의 반복 폴링·전체 파일 재작성·중복 상태 저장소를 선택하지 않는다. 중요한 설계 선택은 기존 구조와 정확성·성능·복구 비용을 기준으로 하며, 단순한 요구에 불필요한 프레임워크를 도입하지 않는다. 변경에 관련된 도메인 규칙·입출력 계약·데이터 흐름·오류/복구·호환성·동시성/자원 수명을 먼저 확인하고, 영향이 큰 선택만 실제 대안과 근거를 비교한다. 정상 경로뿐 아니라 부분 실패·중복 요청·취소·재시작 등 관련 경계에서 데이터와 상태가 보존되는지 코드 리뷰와 필요한 검사로 확인한다. 작은 수정마다 별도 설계 보고서나 전체 아키텍처 재검토를 요구하지 않는다. 최적화는 관련 측정이나 명확한 중복 비용 제거로 근거를 남기고, 효과 없는 우회는 제거한다. 미지원·실패·미검증을 완성된 동작으로 대체하지 않는다.
- 성능에 영향받는 경로에서는 반복 조회/N+1·핫패스 할당·동기 I/O·무제한 큐/캐시·태스크/이벤트 구독의 누수를 확인한다. 같은 입력의 유효한 결과는 재사용하되 실제 변경·버전·권한·수명과 무관한 캐시로 정확성을 잃지 않는다. 변경 목적과 관련 없는 튜닝은 하지 않고, 기존 검증과 필요한 프로파일링으로 판단한다.
- 검증은 현재 요청의 완료 조건을 증명하는 최소 묶음을 한 번 수행한다. 텍스트 내용만 요구하면 read/edit 결과나 diff로 확인하고 같은 파일을 다시 셸로 읽지 않는다. 정확한 바이트·인코딩·줄바꿈·해시가 조건이면 해당 검사를 한 번에 수행해 내용 확인도 함께 끝낸다. 파일 목록·크기·수정 시각 조회를 내용 보존 증거로 대신하거나 이를 이유로 같은 내용을 다시 읽지 않는다. 완료 조건이 모두 확인됐으면 새 실패·외부 변경·미확인 부작용이 없는 한 추가 점검 라운드를 만들지 않고 최종 보고한다. 영향받는 검사부터 하고 공유 코드·API·의존성·통합 영향이 있으면 넓힌다. 저장마다 동일한 전체 빌드를 반복하지 않는다. 성공한 검증은 관련 소스·설정·의존성·환경이 같을 때만 재사용한다. 필요한 검증이 없거나 실행 불가이면 미실행과 한계를 보고한다. 내용 보존은 확인한 내용·diff·해시를 기준으로 판단한다. 내용이 같고 시간 보존 요구가 없으면 수정 시각 차이만으로 외부 편집을 추정해 재검증을 반복하지 않는다. 새 증거 없이 같은 원인에 같은 방법을 반복하는 무진전 시도만 두 번으로 제한한다. 새 근거·수정된 입력·다른 해결 방법으로 진행하는 작업에는 이 횟수를 누적하지 않는다. 재시도 전 불확실한 부작용을 확인하며 사용자 취소·권한 제한은 그대로 따른다.

## 유한 실행·취소·완료

- 셸은 비대화형·유한 timeout·종료 코드·출력 로그를 사용한다. 파일 내용 조회·국소 수정은 read/edit 도구를 우선하며 단순 파일 확인을 위해 셸을 새로 열지 않는다. 서로 독립적인 read·검색은 지원하는 병렬 호출로 같은 모델 응답에서 요청한다. 셸이 필요한 같은 환경의 짧은 독립 조회는 한 호출로 묶어 기동 횟수를 줄이고 각 결과의 대상·실패를 구분한다. 의존 결과가 나오기 전에 다음 쓰기를 실행하거나 재사용 상태를 캐시해 버리지는 않는다. 각 조회의 오류와 종료 코드를 보존하며, 쓰기·설치·승인·의존 작업은 독립 조회 묶음에 섞지 않는다. 짧은 조회는 보통 15~30초, 일반 명령은 120초를 출발점으로 하고 긴 빌드·관측에는 예상 시간과 여유를 명시한다. ACP timeout 0은 120000ms로 보정된다. 고정 sleep 대신 필요한 준비 조건을 기한 안에서 확인하고 충족 즉시 진행한다. 조용한 정상 빌드를 중복 실행하거나 임의 중단하지 않는다.
- Windows ACP는 UTF-8 임시 스크립트와 설치된 PowerShell bootstrap을 사용한다. 직접 실행은 scripts/run_bounded_command.ps1의 -CommandFile을 활용한다. WSL은 배포판·Linux 경로·실행 파일을 명시하고 Windows/WSL 패키지 위치를 섞지 않는다. Linux/macOS는 run_bounded_command.sh를 쓰며 GNU timeout(gtimeout)이 없으면 지원되는 유한 실행기를 사용한다.
- UAC·암호·인증 입력을 요구하는 대화형 승격이나 보안 데스크톱 승인은 시도하지 않는다. 이미 실행 중인 계정이 가진 권한의 비대화형 명령은 현재 작업 범위와 실제 도구 정책 안에서 실행한다. sudo 등 도구 정책이 거부한 경로를 이 지침으로 허용하거나 다른 셸로 우회하지 않는다. 권한이 필요하면 BLOCKED_UAC와 필요한 단일 관리자 명령·이유를 기록한다. 일반 확인은 제한 시간 안의 실제 완료 증거로만 진행하며 없으면 WAITING_FOR_USER_CONFIRMATION으로 기록한다. 차단 단계·의존 작업을 보류하고 이미 허가된 독립 작업만 진행한 뒤 미완료 조건을 보고한다. 늦은 승인은 새 `승인 완료, 계속` 요청에서 소유 대상 상태를 확인한다. 승인 대기·같은 실행 재시도는 하지 않는다.
- Rider/Hermes ACP에서는 필수 셸·하위 작업을 현재 요청 안에서 기다린다. shell/subagent background는 사용하지 않고 충분한 유한 timeout을 지정한다(300초 관측 예: 420000ms). 필수 작업을 남긴 채 중간 안내로 응답을 끝내지 않는다. 이미 실행한 작업은 중복 시작하지 말고 소유 PID·로그·도구 완료 규약으로 결과를 확인한다. 결과가 없으면 검증 미완료로 보고한다.
- 명시적으로 요청한 상시 서버·watcher만 별도 프로세스로 실행하고 PID·로그·health로 시작을 확인한다. 최종 보고에 계속 실행 중임을 밝힌다. 단순 모델 생성의 Strata done은 전체 업무 완료가 아니다.
- 현재 추론에 사용하는 Strata 서버의 코드/설정 변경 적용에 전체 재시작이 필요하고 `strata_restart_server`가 등록되어 있으면, 파일을 저장하고 완료/미완료·관련 경로·남은 검증을 checkpoint에 남긴 뒤 해당 도구를 현재 요청 안에서 기다린다. 불확실한 전달은 같은 operation_id와 checkpoint로 확인하며 새 ID로 재시작을 반복하지 않는다. READY 결과 후 실제 파일 상태와 남은 작업만 확인해 이어가고 완료 작업을 재실행하지 않는다. 관리 도구가 없거나 실패하면 셸에서 자기 서버를 종료하지 말고 미완료 조건을 보고한다. 취소·종료한 요청을 재시작 완료 알림으로 자동 재개하지 않는다. 이 절차는 관리 프로세스 자체·OpenCode·OS 재시작 권한을 포함하지 않는다.
- 완료는 종료 상태다. 수락 조건을 충족하면 필요한 자신 소유 CUA session 정리 후 최종 보고하고 추가 조사·재검증·자동 작업을 시작하지 않는다. 단계 예산은 조기 완료를 금지하는 목표가 아니다. 설정된 agents.build.steps(일반 프리셋 200, 장기 작업 선택값 512; 사용자 지정값 우선) 안에서 남은 조건을 진행하고, 한계 전에 `KOREAN_INSTRUCTIONS.md`의 최종 보고 형식으로 미완료 조건과 다음 행동을 남긴다. 무진전 중단·취소 규칙은 예산과 별개이며 단계 한계나 오류를 성공으로 보고하지 않는다.
- 사용자 중지는 취소이며 복구 재시도·추가 검증·늦은 알림의 자동 재개로 바꾸지 않는다. 이미 저장한 파일을 자동 롤백하지 않는다. 파일 저장·설치·MCP 입력 등 실행된 부작용은 취소만으로 되돌려지지 않는다. 새 요청 없이 후속 작업을 계속하지 않는다.

## MCP 선택·오류·압축

- 도구 선택과 REA 분석/구현 경계는 `KOREAN_INSTRUCTIONS.md`, GUI 입력은 `OPENCODE_CUA_AUTOMATION_KO.md`, 엔진별 작업은 프로젝트 지침을 따른다. GUI 입력 제한을 셸로 우회하지 않는다. 클라이언트 CUA의 화면을 원격 Strata 서버 화면으로 혼동하지 않는다.
- 현재 도구 스키마를 사용하고 매 단계마다 모든 서버의 목록과 사용법을 다시 조회하지 않는다. 부재·스키마 변경·연결 복구 때 필요한 목록만 갱신한다. 유효한 분석/창 ID·결과는 재사용하되 대상 변경·재시작·만료·불일치 때 갱신한다. 독립 읽기만 묶고 의존하는 쓰기·GUI 입력은 순서대로 한다.
- MCP의 isError·오류 코드·실제 결과를 확인한다. 전송 성공은 동작 성공이 아니다. 일시적 연결 오류는 기존의 제한된 재시도를 따르며 별도 루프를 만들지 않는다. 인증·권한·미지원·지속 장애는 반복하지 말고 보존한 작업과 필요한 조치를 보고한다. 서버 재설치·재시작을 반복하지 않는다.
- 잘린 JSON·도구 인자는 실행 여부를 확인해 작은 올바른 호출로 고친다. timeout·연결 끊김은 미실행 증거가 아니므로 결과 파일·diff·소유 프로세스를 확인한다. 클릭·쓰기·설치 등은 실제 상태 확인 없이 재전송하지 않는다. 필요한 재실행을 명령 문자열 중복만으로 막지도 않는다.
- 장문 요청은 전체 토큰 수와 새로 읽는 토큰 수를 구분한다. 바뀌지 않은 코드·로그를 반복 추가하지 않고, 요청 조립 코드에서는 실제 변경 없이 고정 지침·도구 정의를 재정렬하거나 앞부분에 매번 진행 시간·임시 상태를 삽입하지 않는다. 새 요청·도구 결과는 기존 대화 뒤에 이어 붙이고 고정 prefix는 실제 내용이 바뀔 때만 갱신한다. 최신 요청·제약·실제 변경은 캐시 유지를 위해 누락하지 않는다. 길다는 이유만으로 수동 압축·문맥 초기화를 반복하지 않고 설정된 자동 압축을 따른다. 성능을 진단할 때만 재사용 토큰·새 프리필 시간·요약 비용·후속 작업 시간을 함께 비교한다.
- 압축은 현재 요청의 종료가 아니다. 압축기가 요구하는 제목 형식을 유지하고 본문은 한국어로 최신 요청·금지 사항·설계/구현 소유자·관련 경로/심볼·완료/미완료·검증 근거·차단·다음 행동을 하나의 최신 체크포인트에 통합한다. 과거 요약·전체 코드·로그·해결된 오류 경과를 누적하지 않는다. 미완성 파일의 저장된 범위와 남은 범위, 불확실한 부작용과 소유 프로세스는 보존한다.
- 압축·재개 후에는 관련 현재 구간·diff와 남은 조건을 대조한다. 요약보다 실제 상태를 우선하며 완료한 일을 재활성화하지 않는다. 압축만으로 유효한 검증을 무효화하거나 전체 저장소·검사를 처음부터 반복하지 않는다. 기존 인계 문서를 필요할 때만 갱신하고 새 병렬 상태 저장소를 만들지 않는다.
- 산출물 형태·대상 OS·실행/설치 방식·네이티브 요구·오프라인 요구는 기존 체크포인트와 인계에 보존한다. 압축·하위 에이전트 위임·도구 장애·재접속이 웹 전환 허가가 아니다. 완료 전에 요구한 실행/배포 경로와 실제 결과를 대조하고, 빌드/플랫폼 검증을 못 했으면 미검증으로 남긴다.
