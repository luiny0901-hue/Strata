# Unreal Engine 프로젝트 지침

## 시작 전 확인

- `.uproject`의 `EngineAssociation`, 프로젝트가 정한 Unreal Engine 버전, 대상 플랫폼과 기존 빌드·테스트 명령을 먼저 확인한다. 버전·플러그인·생성 파일·프로젝트 설정을 추측으로 바꾸지 않는다.
- 기존 `Source/` 모듈, `.Build.cs`, `.Target.cs`, `Config/`, 자동화 테스트와 CI 설정을 먼저 찾는다. 같은 역할의 GameInstance, Subsystem, Component, Manager, Ability System을 두 번째로 만들지 않는다.

## 구조와 구현

- 게임 기능은 가장 가까운 기존 C++ 모듈 또는 명확한 새 모듈 하나가 소유한다. Public 헤더는 실제 모듈 간 API만 두고, 구현은 Private에 둔다. 모듈 의존성은 한 방향으로 유지하고 순환 의존성을 만들지 않는다.
- Blueprint는 명확한 게임플레이 조립·데이터 역할에 사용하고, 상태·규칙·반복 로직을 여러 Blueprint와 C++에 중복 구현하지 않는다. C++와 Blueprint의 소유 경계를 변경하면 이유와 영향 범위를 기록한다.
- `.uasset`, `.umap`, 바이너리 에셋과 엔진 생성 파일을 텍스트 편집기로 임의 수정하지 않는다. 에디터 조작이 필요한 경우 정확한 에셋·창·결과를 확인하고, 사용자가 요청하지 않은 대규모 리저장·리다이렉터 정리·에셋 이동은 하지 않는다.
- `Config/Default*.ini` 변경은 관련 설정의 기존 소유 파일만 수정하고, 플랫폼·입력·렌더링 전역값을 추측으로 바꾸지 않는다.

## 그래픽·플레이·UI 품질

- 아트 방향, 대상 기기·해상도·FPS/프레임 시간·CPU/GPU·메모리 예산을 요구에서 확인한다. 미정인 값은 합리적 가정을 밝히고 진행하며 결과를 바꾸는 중요한 선택만 확인한다.
- 엔진 버전·RHI·대상 플랫폼에 맞춰 렌더링 기능을 선택한다. Nanite·Lumen·레이 트레이싱·그림자·업스케일링을 일괄 최대화하지 않는다. 실제 지원·시각 차이·프레임 비용과 프로젝트의 기존 설정을 근거로 결정한다.
- 카메라·노출·조명·PBR 재질·텍스처 밀도·캐릭터/환경·애니메이션·VFX·HUD를 같은 아트 방향으로 맞춘다. 대표 플레이 구간에서 이동·상호작용·전투 등 실제 흐름을 먼저 완성한 뒤 전체 범위로 확장하며 시네마틱 한 장을 플레이 품질로 대신하지 않는다.
- Unreal Insights·GPU 측정 등 해당 버전에서 제공하는 도구로 실제 대상 기기의 프레임 시간·히치·메모리·스트리밍·셰이더 준비 비용을 확인한다. LOD/HLOD·텍스처/월드 스트리밍·품질 단계는 측정된 병목에 맞게 사용한다. 개발 PC 에디터 FPS만으로 출시 성능을 판정하지 않는다.
- UI는 기존 UMG/Slate/Common UI 구성과 입력 장치에 맞춰 일관된 컴포넌트·타이포그래피·포커스·대비·한글 글꼴·화면 비율/안전 영역·로딩/빈 화면/오류/복구를 다룬다. 최신 유행만으로 기존 디자인 체계를 교체하지 않는다.
- 에셋 출처·라이선스·플랫폼 호환성을 확인한다. 필요한 에셋·도구가 없으면 최종 품질이라고 주장하지 않는다. 화면 비교는 같은 플레이 상황·카메라·해상도·품질 설정을 사용한다.

## 검증과 보고

- 프로젝트가 제공하는 Unreal Build Tool, Automation Test, 정적 분석, 포맷 명령만 사용한다. 에디터, Cook, Package, 셰이더 전체 컴파일, 서버는 요청 또는 문서화된 검증 절차 없이는 시작하지 않는다.
- 변경 후에는 관련 C++ 컴파일·Automation Test·에셋 참조 검증을 실행한 사실과 결과를 기록한다. 실행할 수 없는 엔진·플랫폼 검증은 `NOT_RUN`으로 남긴다.
- 완료 보고에는 기존 기능 소유자, 수정한 모듈·에셋, 새 의존성, 실행한 검증, 미실행 검증, 남은 위험을 적는다.
