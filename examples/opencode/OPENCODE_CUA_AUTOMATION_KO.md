# GUI 작업

- 구체적으로 요청한 작업에 화면 확인·조작이 필요하면 연결된 `cua-driver_*` 도구를 사용한다. 파일·코드·일반 셸 작업에는 GUI를 열지 않는다.
- GUI·권한·확인 단계가 막히면 그 단계와 의존 작업만 보류한다. 현재 요청 안의 독립적인 코드 수정·정적 분석·테스트 준비는 계속하고, 끝에서 완료한 부분과 차단된 검증을 구분한다. 같은 입력을 재전송하거나 사용자 입력을 우회하지 않으며 모든 필수 조건을 충족하지 못하면 전체 완료로 보고하지 않는다. 사용자 중지·취소가 오면 독립 작업도 멈춘다.
- 사용자의 작업·게임을 방해하지 않는다. 새 GUI 앱 실행, 창 활성화·이동·최소화, foreground/global 입력과 사용자 포인터 조작을 하지 않는다. 이 프록시는 포커스를 가져올 수 있는 launch_app을 노출하지 않는다. 대상 앱이 없으면 사용자에게 열어 달라고 보고하고 독립적인 코드 작업을 진행한다. 셸로 GUI 앱을 띄워 제한을 우회하지 않는다.
- 사용자가 같은 창에 입력 중이거나 화면이 계속 변해 표적을 확정할 수 없으면 해당 GUI 입력을 보류하고 충돌을 보고한다. 포커스를 강제로 복원하거나 사용자 입력과 경쟁하지 않는다. 이것은 행동 지침이며 사용자 입력·게임 상태를 자동으로 완벽히 감지하는 기능은 아니다. 입력 충돌 없는 동시 작업이 필수라면 별도 PC·VM 등 독립된 GUI 세션이 필요하다.
- 모니터 해상도·배율·화면 위치가 달라도 반환 스크린샷 좌표만 사용한다. 창 이동·크기 변경·새 창·실패한 화면 조회 뒤에는 기존 픽셀을 재사용하지 않는다. stale_capture 응답의 그림·토큰은 입력 근거가 아니며 새 상태를 읽는다. 백그라운드 입력 미지원·최소화 캡처 실패·게임의 전용 입력·UAC·보호 화면은 우회하지 않는다.
- 시작 때 `list_windows`로 정확한 PID/창 ID를 식별하고 `get_window_state`로 화면을 읽는다. 동일 창에서는 목록을 재사용하며 앱 재시작·새 창·ID 불일치 때 다시 찾는다.
- 표준 컨트롤은 최신 `element_token`으로 조작한다. 좌표는 최근 스크린샷에 보이는 접근성 없는 표면에서만 사용한다. 입력 후 결과를 확인하고 새 snapshot의 토큰으로 진행한다.
- 픽셀 좌표는 반환 PNG의 왼쪽 위가 (0,0)인 이미지 내부 좌표다. 화면 절대좌표·UIA frame 좌표·0~1000 정규화 좌표를 혼용하거나 DPI·비전 토큰 크기로 재보정하지 않는다. 프록시는 이미지 크기를 `CUA_COORDINATES`로 알려준다. `move_cursor`도 이 좌표를 쓰며 화면 절대좌표 변환은 프록시가 맡는다. 커서 이동 없이 바로 클릭할 수 있다. 한 번 입력한 뒤 다음 픽셀 입력 전에는 새 스크린샷을 읽고 확인한다. `fresh_screenshot_required`는 클릭 미실행이므로 화면을 다시 확인하고 정확한 표적을 고른다. 오차를 짐작해 여러 위치를 연속 클릭하지 않는다.
- 접근성 정보가 충분하면 `since:snapshot_id`, `include_screenshot:false`로 변경 트리만 읽는다. 캔버스·픽셀 변화·빈 트리·불확실한 결과에는 스크린샷이 필요하다. 큰 트리는 query/max_depth/max_elements로 좁히고, 잘린 정보를 추측하지 않는다.
- 정확한 같은 창에 `delivery_mode:"background"`만 사용한다. AI 전용 커서는 `move_cursor` 오버레이만 사용하며 사용자 마우스·물리 포인터·foreground·SendInput을 사용하지 않는다. `background_unavailable` 또는 확인된 무동작이면 `BACKGROUND_ONLY_UNSUPPORTED`로 멈추고 보고한다. 사용자 마우스로 전환하거나 셸/네이티브 입력으로 우회하지 않는다.
- 데스크톱 전체 입력, 권한 우회, 셸/네이티브 입력 우회는 금지한다. 권한 거부는 중단 사유다. stale 토큰은 새 상태로 한 번만 재표적화한다. PostMessage 성공만으로 UI 성공이라 하지 않는다.
- UAC 보안 데스크톱은 CUA로 승인하지 않는다. `BLOCKED_UAC`와 필요한 사용자 조치를 기록하고 해당 GUI 단계는 보류한다. 승인 대기·폴링·재시도는 금지하며 허가된 독립 코드 작업만 이어갈 수 있다.
- 일반 확인 창은 정확히 식별한 소유 대상의 실제 완료 증거로만 다음 의존 작업을 진행한다. 제한 시간 안에 끝나지 않으면 `WAITING_FOR_USER_CONFIRMATION`으로 해당 단계를 보류한다. 늦은 승인은 새 `승인 완료, 계속` 요청에서 한 번만 재확인하며 같은 실행·클릭은 반복하지 않는다.
- 끝나면 자신이 만든 session/커서를 정리한다. 실제 화면에서 확인한 결과만 한국어로 보고한다.
