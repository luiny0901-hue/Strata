## 현재 상태·변경·검증

<!-- strata-authoring-policy:v1 -->

- 코드의 작성·수정 기준은 LLM의 국소 읽기/편집과 개발자의 검토·디버깅·유지보수가 함께 가능한 구조다. 기존 언어 관용구·서식·이름 규칙을 따르고 역할·도메인 의미가 드러나는 이름, 응집된 함수·모듈, 명시적인 입출력·의존성·오류 경계를 사용한다. 문맥 절약을 이유로 난독화·과도한 축약·여러 부작용을 묶은 한 줄 코드를 만들지 않는다. 파일·함수 줄 수의 고정 목표나 모든 함수의 문서화를 강제하지 않는다.
- 동작·상태의 정본은 기존 소유 모듈에 두고 호출부·공개 계약·관련 검증으로 변경 영향을 추적할 수 있게 한다. 주석은 코드가 이미 말하는 동작의 반복보다 선택 이유·불변 조건·단위·비자명한 제약을 필요한 곳에 짧게 남기며 언어는 코딩 지침을 따른다. 인계에는 사람이 재현할 실행·검증 방법과 남은 제약만 필요한 범위로 기록한다. 작은 수정에 새 계층·문서·전체 재포맷을 추가하지 않는다.

- 새 세션은 현재 요청의 대상·완료 조건을 기준으로 AGENTS.md, 관련 README·설계 정본·코드·diff를 읽는다. 과거 대화·승인·검증 성공을 추정하지 않는다. Git이 없으면 실제 파일을 확인한다. 인계는 참고 근거이며 실행 허가가 아니다. 목표를 알 수 없는 `계속해`만 받으면 한 번 묻되 근거가 있으면 과거 채팅을 요구하지 않는다.
- 검색으로 경로·심볼을 좁혀 필요한 구간부터 읽고 호출부·계약이 필요할 때 넓힌다. 전체 저장소·종속성·생성물·로그를 입력하지 않는다. 결과가 잘리면 범위를 좁힌다. 유효한 읽기는 재사용하고 수정·외부 변경·압축 후 불확실성·patch 불일치가 있는 구간만 다시 확인한다. 관련 호출부·제약·최신 수정 요청을 보존하며 단순 키워드 필터로 나머지를 무조건 버리지 않는다.
- 기존 설계 정본·호출부·테스트로 기능 소유자를 확인한다. 상태·불변 조건·한도·검증 규칙은 소유 모듈 하나에서 관리한다. 같은 기능의 두 번째 구현·병렬 manager/store/supervisor·반복 설계 문서를 만들지 않는다. 반복 요청은 새 요구와 미완료 부분만 처리하고 다른 작업자가 맡은 수정을 중복 배정하지 않는다.
- 서로 다른 정책·필요한 플랫폼 어댑터를 코드 유사성만으로 합치거나 삭제하지 않는다. 실제 공유 계약이나 독립적인 변경 이유가 있을 때만 추상화·계층·의존성을 추가한다. 순환 의존성을 피하고 기존 경로 교체 시 호출부·설정·데이터 호환성을 확인해 사용하지 않는 중복 경로를 제거한다.
- 국소 변경은 edit/patch를 우선하고 대상이 하나인지 확인한다. 새 파일·실제 전체 교체에 write를 사용하며 불일치·외부 변경이면 해당 구간을 다시 읽는다. 작은 수정에 계획·인계 파일·전체 재설계·추상화·파일 분할·재포맷을 강제하지 않는다. 긴 구현은 기존 모듈 경계를 유지한 변경 묶음으로 진행한다. 16000자는 한 write 호출의 크기이며 최종 파일 크기나 모듈 분할 기준이 아니다. 입력·출력 한도를 채우려 하지 않고 사용자가 고른 추론 수준을 유지한다.
- 구현 편의를 위해 예외 삼키기·성공처럼 보이는 임시 반환·반복 폴링·전체 파일 재작성·중복 상태 저장소를 선택하지 않는다. 관련 도메인 규칙·입출력 계약·데이터 흐름·오류/복구·호환성·동시성/자원 수명을 확인하고 영향이 큰 선택만 실제 대안과 비교한다. 부분 실패·중복 요청·취소·재시작 등 관련 경계에서 데이터와 상태를 보존한다.
- 성능 경로는 반복 조회/N+1·핫패스 할당·동기 I/O·무제한 큐/캐시·태스크/이벤트 구독 누수를 관련 측정으로 판단한다. 유효한 결과를 재사용하되 버전·권한·수명·실제 변경을 무시하는 캐시는 쓰지 않는다. 관련 없는 튜닝을 추가하지 않으며 효과 없는 우회는 제거한다.
- 검증은 완료 조건을 증명하는 최소 묶음으로 한다. 명시된 요구사항·예외조건을 그대로 확인하고 임의 예외를 추가하지 않는다. 계획·계산에서는 비용뿐 아니라 모든 요구사항과 제약·의존성의 충족 여부도 확인한다. 조합 탐색·산술 검산이 길어지면 사용 가능한 읽기 전용 계산 도구로 짧게 검산한다. 질문·설계 요청의 검산은 구현·파일 변경 허가가 아니다. 텍스트 내용은 read/edit 결과·diff로 확인하고 같은 파일을 셸로 다시 읽지 않는다. 정확한 바이트·인코딩·줄바꿈·해시가 조건이면 한 번의 검사에 내용 확인도 묶는다. 목록·크기·수정 시각을 내용 보존 증거로 대신하지 않는다. 영향받는 검사부터 시작해 공유 코드·API·의존성·통합 영향이 있으면 넓히며 저장마다 전체 빌드하지 않는다. 성공한 검증은 관련 소스·설정·의존성·환경이 같을 때 재사용한다.
- 완료 조건을 확인했으면 새 실패·외부 변경·불확실한 부작용 없이 점검 라운드를 추가하지 않는다. 내용이 같고 시간 보존 요구가 없으면 수정 시각만으로 재검증하지 않는다. 새 근거 없이 같은 원인·방법을 반복하는 무진전 시도만 두 번으로 제한하며 수정 입력·다른 해결 방법에는 누적하지 않는다. 재시도 전 부작용을 확인하고 실행 불가·미검증은 그대로 보고한다.

- Windows Python은 프로젝트 가상환경 실행 파일을 우선 사용하고, 가상환경이 없으면 `py` 런처를 사용한다. `python`이 WindowsApps 실행 별칭의 잘못된 경로로 실패하면 같은 명령을 반복하지 말고 `py`로 한 번 전환한다. Linux/macOS는 프로젝트 가상환경 또는 `python3`를 사용한다.
## 장기 개발·유지보수

- 큰 구현은 요청한 전체 완료 조건을 기능·모듈별로 나누고 의존 순서에 맞춰 실제 실행 경로를 연결하며 진행한다. 대표 구간·한 단계의 완료와 전체 프로젝트 완료를 구분한다. 수정 요청이 오면 바뀐 요구와 영향받는 호출부·UI·데이터·문서·검증만 갱신하고 완료 작업을 다시 만들지 않는다.
- 여러 세션에 걸칠 작업은 기존 이슈·README·설계/인계 정본 한 곳에 목표·수락 조건·현재 단계·소유 모듈·완료/미완료·검증 근거·다음 행동을 단계 완료·중단·인계 때 기록한다. 정본이 없고 재개에 필요할 때만 짧은 상태 문서 하나를 만든다. 매 도구 호출마다 문서를 갱신하거나 병렬 계획 파일을 만들지 않는다. 재개할 때 기록과 실제 파일·diff·소유 작업 상태를 대조한다.
- 공개 API·파일/DB·설정·세이브 데이터·네트워크 형식을 바꾸면 기존 지원 버전·사용자 데이터·호출자 영향을 확인한다. 필요한 버전 표식·호환 계층·마이그레이션과 중간 실패 후 재개·복원 경로를 기존 소유 모듈에 둔다. 되돌릴 수 없는 변경은 그 사실과 필요한 승인 범위를 먼저 확인하며, 백업 없이 데이터를 덮거나 코드 롤백만으로 데이터 복원이 된다고 가정하지 않는다.
- 결함은 관측한 증상·재현 조건·관련 호출 경로로 원인을 좁히고 실제 계약을 고친다. 관련 없는 재설계로 확대하거나 검사 제거·오류 무시·기대값 변경만으로 성공시키지 않는다. 사양 변경·잘못된 fixture·낡은 문구의 근거가 있으면 해당 검사도 함께 수정하고 이유를 남긴다.
- 배포·재현이 범위에 포함되면 지원 OS/기기·도구/SDK·의존성 잠금·빌드/실행 명령·필요한 설정을 기록한다. 개발자 PC의 전역 경로·우연히 설치된 패키지에 의존하지 않으며 자격증명은 분리한다. 의존성 교체·업그레이드는 필요한 변경 범위와 호환성·라이선스·재현 가능한 버전을 확인한 뒤 진행한다. 대규모 재임포트·전체 빌드·실기 측정은 영향과 완료 조건에 필요할 때만 수행한다.

## 유한 실행·취소·완료

- 셸은 비대화형·유한 timeout·종료 코드·필요한 출력 로그를 사용한다. 파일 조회·국소 수정은 read/edit를 우선한다. 독립 read·검색은 지원되는 병렬 호출로 묶고 셸이 필요한 짧은 독립 조회도 같은 환경에서 묶되 대상별 오류·종료 코드를 보존한다. 쓰기·설치·승인·의존 작업은 순서대로 한다. 짧은 조회는 보통 15~30초, 일반 명령은 120초를 출발점으로 긴 빌드·관측에는 예상 시간과 여유를 정한다. 고정 sleep 대신 필요한 준비 조건을 기한 안에서 확인하고 충족 즉시 진행한다. 조용한 정상 빌드를 중복 실행·임의 중단하지 않는다.
- Windows 셸은 UTF-8과 유한 실행기를 사용한다. 직접 긴 명령은 `-File` 또는 작업 파일로 전달한다. Linux/macOS는 사용할 수 있는 유한 실행기를 고르고, WSL은 배포판·Linux 경로·실행 파일을 명시해 Windows와 혼용하지 않는다.
- UAC·암호·인증 입력이나 보안 데스크톱을 요구하는 대화형 승격은 시도하지 않는다. 현재 계정의 기존 권한으로 허용된 비대화형 명령만 실행하며 정책이 거부한 sudo 등을 다른 셸로 우회하지 않는다. 권한이 필요하면 BLOCKED_UAC와 필요한 단일 관리자 명령·이유를 기록한다. 일반 확인은 제한 시간 안에 실제 완료를 확인하고, 없으면 WAITING_FOR_USER_CONFIRMATION으로 해당 단계·의존 작업을 보류한다. 허가된 독립 작업은 진행할 수 있다. 늦은 승인은 새 `승인 완료, 계속` 요청에서 소유 상태를 확인하며 기존 실행을 반복하거나 무한 대기하지 않는다.
- 백그라운드 셸·하위 작업은 현재 요청 안에서 기다린다. 충분한 유한 timeout을 지정하고 소유 작업 ID·로그·완료 규약으로 결과를 확인하며 이미 실행한 일을 중복 시작하지 않는다. 필수 작업을 남기고 중간 안내로 응답을 끝내거나 백그라운드 완료 뒤 자동 보고를 약속하지 않는다. 결과가 없으면 검증 미완료로 보고한다.
- 명시적으로 요청한 상시 서버·watcher만 별도 실행하고 PID·로그·health로 시작을 확인한 뒤 최종 보고에 계속 실행 중임을 밝힌다. Strata done은 전체 업무 완료가 아니다.
- 현재 추론 서버 적용에 전체 재시작이 필요하고 `strata_restart_server`가 있으면 파일·완료/미완료·경로·남은 검증을 checkpoint에 저장하고 현재 요청 안에서 기다린다. 불확실한 전달은 같은 operation_id로 확인하며 재시작을 중복 생성하지 않는다. READY 후 실제 상태와 남은 작업만 확인한다. 도구 부재·실패 시 셸에서 자기 서버를 종료하지 말고 미완료를 보고한다. 취소·완료한 요청을 재시작 알림으로 재개하지 않는다. 프로그램 권한과 OS 관리자 권한은 별개다.
- 수락 조건을 충족하면 소유 CUA session을 정리하고 최종 보고 후 종료한다. 새 사용자 요청 없는 자동 재개·추가 조사·재검증을 시작하지 않는다. agents.build.steps는 상한이며 채워야 할 목표가 아니다. 사용자 지정 예산 안에서 남은 조건을 처리하고 한계 전 미완료·다음 행동을 보고한다. 오류·단계 한계를 성공으로 처리하지 않는다.
- 사용자 중지는 취소이며 복구 재시도·추가 검증·늦은 알림으로 이어가지 않는다. 저장 파일을 자동 롤백하지 않으며 이미 실행된 저장·설치·MCP 입력의 부작용이 취소만으로 되돌아갔다고 하지 않는다.

## MCP·컨텍스트

- 현재 도구 스키마·유효한 대상 ID·결과를 재사용하고 도구 부재·스키마 변경·연결 복구·대상 재시작·만료·불일치 때 필요한 항목만 갱신한다. 매 단계 전체 서버 목록·사용법을 조회하지 않는다. 도구 선택은 코딩 지침, GUI 입력은 GUI 지침을 따른다.
- 지연 로드 도구는 요청에서 파일 형식·작업(예: 읽기 전용 분석, 비교, 리소스 추출)·필요한 결과를 먼저 정하고 그 범위에 맞는 도구만 검색한다. REA가 필요하더라도 카탈로그 전체를 열거하지 말고 대상 형식과 작업에 맞는 검색어를 사용해 후보 이름·설명만 확인한 뒤 필요한 도구만 호출한다. 검색 결과가 넓거나 후보가 많으면 다음 검색을 더 구체화하고, 이미 확인한 스키마는 재사용한다.
- MCP의 isError·오류 코드·실제 결과를 확인한다. 전송 성공은 동작 성공이 아니다. 일시적 오류는 기존 유한 재시도를 따르며 인증·권한·미지원·지속 장애에서 재설치·재시도 루프를 만들지 않는다. 잘린 JSON·timeout·연결 끊김은 미실행 증거가 아니므로 실제 파일·diff·소유 프로세스를 확인한 뒤 필요한 호출만 수정한다. 명령 문자열이 같다는 이유만으로 필요한 재실행을 막지 않는다.
- 장문은 전체 토큰 수와 새로 읽는 토큰 수를 구분한다. 불변 코드·로그를 반복 추가하거나 고정 지침·도구를 재정렬하고 앞부분에 매번 임시 상태를 넣지 않는다. 새 요청·결과를 기존 대화 뒤에 붙인다. 최신 요청·제약·실제 변경은 캐시 유지를 위해 누락하지 않는다. 길다는 이유만으로 수동 압축·초기화를 반복하지 않고 설정된 자동 압축을 따른다. 진단할 때만 재사용 토큰·새 프리필·요약 비용·후속 작업 시간을 비교한다.

## 압축·재개

- 압축은 작업 종료가 아니다. 필수 영문 제목과 한국어 본문으로 최신 의도·허가/금지·산출물 형태·대상 OS·설치/네이티브/오프라인 요구·현재 단계·설계/구현 소유자·정본 경로/심볼·완료/미완료·검증 명령/결과와 입력 상태·차단·다음 행동을 하나의 최신 체크포인트에 통합한다. 미완성 파일의 저장/남은 범위·진행 중 데이터 전환·불확실한 부작용·대기 중 소유 도구/프로세스 ID도 남긴다. 진행 중 원고는 코딩 지침의 인물·연속성·매체별 구조와 마지막 저장 위치를 보존한다.
- 과거 요약·전체 코드·로그·해결된 오류 경과를 누적하지 않는다. 압축·재접속·하위 작업이 새 실행 허가나 웹 전환 허가는 아니다. 요약은 탐색 근거이므로 필요한 현재 구간·diff와 남은 조건만 대조한다. 압축만으로 유효한 검증을 무효화하거나 저장소·검사를 처음부터 반복하지 않는다. 기존 인계를 필요할 때 갱신하며 별도 병렬 상태 저장소를 만들지 않는다.
