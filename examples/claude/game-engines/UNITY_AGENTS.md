# Unity 프로젝트 지침

## 시작 전 확인

- `ProjectSettings/ProjectVersion.txt`, `Packages/manifest.json`, `Packages/packages-lock.json`, 기존 CI·테스트·빌드 명령을 먼저 확인한다. Unity 버전·패키지·렌더 파이프라인·플랫폼 설정을 추측으로 변경하지 않는다.
- 기존 `Assets/` 코드, Assembly Definition (`.asmdef`), 테스트, ScriptableObject, MonoBehaviour, 서비스·시스템·매니저를 먼저 찾는다. 같은 역할의 두 번째 manager/store/service 또는 병렬 상태 모델을 만들지 않는다.

## 구조와 구현

- 기능은 가장 가까운 기존 assembly와 공개 API 하나가 소유한다. runtime/editor/test assembly 의존성은 한 방향으로 유지하고 순환 참조를 만들지 않는다. Editor 전용 코드는 runtime assembly에 넣지 않는다.
- ScriptableObject는 데이터와 설정의 소유 경계를 명확히 하고, 게임 상태·규칙을 Scene, Prefab, MonoBehaviour, static singleton에 중복 저장하지 않는다.
- Scene·Prefab·`.asset` YAML은 허가된 기능에 필요한 에셋 범위에서만 변경한다. 직렬화 의미를 확인하지 못한 직접 병합·대량 치환·GUID 수정은 하지 않는다. 필요한 에셋 이동은 원본과 `.meta`의 연결·기존 참조를 보존하는 지원 경로로 처리한다. 에디터 GUI가 필요하면 대상과 결과를 화면에서 확인한다.
- `ProjectSettings/`와 `Packages/` 변경은 관련 파일·패키지의 기존 소유 범위 안에서만 한다. 자동 업그레이드·재임포트·Library 삭제는 요청 없이는 하지 않는다.

## 그래픽·플레이·UI 품질

- 대상 기기·해상도·프레임 시간/FPS·CPU/GPU·메모리 예산과 아트 방향을 프로젝트 요구에서 확인한다. 정해지지 않은 값은 작업을 막지 않는 합리적 가정을 밝히고, 결과에 큰 영향을 주는 미결정 사항만 확인한다.
- 기존 렌더 파이프라인과 해당 Unity 버전의 기능·플랫폼 지원을 확인한다. HDRP를 품질의 동의어로 취급하거나 URP/Built-in을 이유 없이 교체하지 않는다. 조명·노출·재질·텍스처 밀도·색 관리·후처리·카메라를 일관된 시각 목표에 맞춘다.
- 모델/텍스처·LOD·오클루전·배칭/인스턴싱·셰이더 변형·스트리밍은 실제 병목에 맞게 선택한다. 에셋 해상도와 효과 수를 무조건 높이지 않으며, 목표 기기의 Unity Profiler·Frame Debugger 등 사용 가능한 근거로 프레임 지연·GC 할당·메모리와 로딩을 확인한다.
- 게임플레이·조작감·캐릭터/카메라 애니메이션·전투/이동 피드백·VFX·HUD를 대표 플레이 구간에 먼저 연결하고 요청한 전체 기능으로 확장한다. 스틸 이미지·고정 카메라·프리미티브 목업을 최종 인게임 품질로 보고하지 않는다.
- UI는 입력 장치·화면 비율·안전 영역·문자 확대·한글 글꼴·대비·포커스·색 이외의 정보 표현과 로딩/빈 화면/실패/복구를 포함한다. 실제 사용할 UI 기술과 기존 컴포넌트를 재사용한다.
- 에셋의 출처·라이선스·성능 비용을 확인한다. 생성 도구·에셋·에디터가 없으면 가짜 완료 대신 필요한 리소스와 미검증 구간을 보고한다. 화면 비교는 같은 카메라·품질 설정·해상도·조명 조건을 사용한다.

## 검증과 보고

- 프로젝트의 Unity Test Framework, Batch Mode, 컴파일·포맷·정적 분석 명령을 우선한다. 명령이 없으면 설치 버전의 공식 도구·도움말로 확인하며 옵션을 추측하지 않는다. 허가된 구현·수정의 완료 조건에 필요한 에디터·Play Mode·플랫폼 빌드·패키징은 같은 작업 범위에서 수행하고 매 단계 승인을 다시 묻지 않는다. 관련 없는 전체 import·버전 변경은 시작하지 않는다. 실제 GUI 입력은 CUA의 승인 경계를 따른다.
- 변경 후에는 관련 Edit Mode/Play Mode 테스트, C# 컴파일, asmdef 영향과 에셋 참조 검증을 실행한 사실과 결과를 기록한다. 실행할 수 없는 엔진·플랫폼 검증은 `NOT_RUN`으로 남긴다.
- 완료 보고에는 기존 기능 소유자, 수정한 assembly·Scene·Prefab·에셋, 새 의존성, 실행한 검증, 미실행 검증, 남은 위험을 적는다.

## 역할·결과 판정

메인 에이전트가 통합을 소유하고 필요할 때만 설계·게임 시스템·그래픽/에셋·품질 관점을 적용한다. 단일 모델에서 모든 역할을 별도 호출하지 않는다. 기능·임시 에셋·최종 아트/애니메이션·플레이·성능·패키징 상태를 구분하며 임시 도형과 UI를 최종 품질로 보고하지 않는다.
