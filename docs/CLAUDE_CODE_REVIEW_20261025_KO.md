# Claude Code + Strata 추가 점검

2026-10-25, Windows Claude Code 2.1.308과 `qwen3.8-flash-next-unsloth-ud-iq4_xs`를 대상으로 확인했습니다. Claude 실행기와 지침, MCP, 컨텍스트·연결 설정, 서버의 Anthropic 도구 변환을 수정했습니다. 기존 OpenCode·Rider 연결과 모델·Pack·GPU 설정을 새로 구성하지 않았습니다.

## 수정 내용

| 항목 | 수정 |
| --- | --- |
| 엔진 지침 누락 | Unity의 `ProjectSettings/ProjectVersion.txt`, Unreal의 `.uproject` 표식으로 기존 정본 지침 하나를 선택해 SessionStart에 전달합니다. 시작·재개·clear·압축·fork에 적용하며 일반 프로젝트에는 추가하지 않습니다. 새 프로젝트와 다른 엔진 하위 프로젝트는 지정 지침의 경로를 제공합니다. |
| 인코딩 | Windows에서 직접 Python으로 실행해도 훅/MCP의 표준 입출력을 UTF-8로 고정합니다. cp949를 물려받은 환경과 한글 프로젝트 경로도 검사했습니다. |
| 낡은 설정 | 실행 시 관리 대상 지침·MCP·모델 설정을 갱신합니다. 개인 추론 값·권한·훅과 추가 MCP는 보존하며 수동 변경한 생성 지침은 덮어쓰지 않습니다. |
| 컨텍스트 | 실제 서버 한도와 설정값 중 작은 값을 사용합니다. 출력 토큰을 확보하고 남은 창이 100K 미만이면 Claude의 기본 자동 압축을 사용합니다. 262,144에서는 출력 32,000·압축 창 196,608을 유지합니다. |
| 연결 확인 | 서버 준비 상태·모델 ID·컨텍스트를 확인합니다. 다른 공급자의 전역 OpenCode 설정이 있어도 별도 Strata 클라이언트 설정을 찾습니다. 주소의 사용자 정보·쿼리·잘못된 포트를 거부하고 키 원문을 설정에 저장하지 않습니다. |
| 끊어진 지침 참조 | Claude 프로필에서 불러오지 않는 OpenCode 전용 문서에 의존하던 문구를 현재 Claude 실행 지침으로 연결했습니다. |
| 도구 정의 낭비 | `defer_loading: true`인 도구는 바로 렌더링하지 않습니다. 검색 결과 `tool_reference`나 이전 실제 `tool_use`가 있는 도구는 지연 표시가 남아 있어도 사용할 수 있게 합니다. 원래 지연 로딩을 쓰지 않는 요청과 OpenAI 변환 경로의 동작은 유지합니다. |

엔진 표식 확인은 재귀적인 Assets/Library/빌드 폴더 검색을 하지 않습니다. 가까운 부모 디렉터리와 제한된 파일 목록만 확인합니다. 엔진 설치·버전 갱신·프로젝트 파일 추가·에셋 재임포트를 자동으로 실행하지 않습니다.

## 측정과 검증

도구 208개(REA 207개 + 검색 도구)를 넣은 동일 요청을 실제 `/v1/messages/count_tokens`로 계산했습니다.

| 상태 | 입력 토큰 |
| --- | ---: |
| 수정 전 | 50,931 |
| 수정 후 | 281 |

미사용 정의가 빠지는지 확인하는 작은 고정 요청입니다. 일반 코딩 대화 전체에서 같은 비율로 줄거나 작업 완료 시간이 같은 비율로 단축된다는 뜻은 아닙니다. 기존 REA compact 스키마 설정도 유지합니다.

- 관련 Python 회귀 검사 **87개 통과**: 클라이언트, 지연 도구, 기존 프런트엔드, 추론 경로, 컨텍스트 초과, 보안 처리. 컨텍스트 초과·짧은 생각 응답 검사는 의도한 400/length 로그를 발생시켰고 검사 결과는 통과했습니다.
- 실제 Claude → Strata 요청에서 Unity 지침·Unreal 지침·일반 프로젝트의 지침 제외를 확인했습니다. 각 시험 파일 Read 1회, 파일 변경 없음. 이 지침 검사는 격리된 프로필과 진단 프록시를 사용했으며 프록시는 시험 후 종료했습니다.
- 관리 서버가 유휴 상태임을 확인하고 수정한 Python 변환을 적용해 재시작했습니다. 36.26초 후 관리 상태 `ready`, 모델 준비와 슬롯 유휴를 확인했습니다.
- 설치된 실행기로 파일 읽기·Edit·저장·실제 셸 검증 **25.15초**, 같은 대화 후속 수정 **12.10초**, 설명만 하는 후속 질문 **8.10초**, MCP 검색·CUA/REA 실제 조회 **20.47초**에 성공했습니다. 입력·캐시·작업 조건이 다른 과거 결과와의 속도 비교는 하지 않았습니다.
- 질문 단계에서는 변경 도구와 셸 실행이 없었고 파일 해시가 유지됐습니다. 코드 시험 전체에서 입력 파일과 보호 파일이 보존됐습니다.
- 기존 OpenCode JSON, Rider ACP JSON, portable-profile JSON의 해시가 유지됐습니다. API 키 원문은 새 설정·지침에 넣지 않았습니다.

## 실패·재시도 기록

첫 엔진 자동 연결 시험에서는 전용 설정 폴더의 경로별 규칙이 자동 로드되는 것으로 확인되지 않았습니다. 이를 성공으로 처리하지 않고 프로젝트 표식에 따른 기존 SessionStart 훅으로 바꿨습니다.

두 후속 엔진 검사는 한국어 제목을 실제 요청에서 찾지 못해 실패했습니다. 요청을 확인한 결과 직접 실행 환경의 cp949 훅 출력이 UTF-8로 해석돼 한글이 깨졌습니다. ASCII 표식 검사는 통과했지만 이것만으로 한글 정상이 증명되지 않아 UTF-8 처리 후 한국어 제목과 대체 문자 부재까지 다시 검사했습니다. 최종 검사는 모두 통과했습니다. 이전 스크립트·실패 로그는 덮어쓰지 않았습니다.

기록: `C:\Users\luiny\Strata-data\diagnostics\claude-code-review-20261025`. 원래 설치 시험 기록도 별도 유지합니다. 서버와 클라이언트 변경 전 파일, 재시작 영수증과 입력 토큰 요청도 보관했습니다.

## 검증하지 않은 범위

Unity/Unreal 에디터 실행·실제 엔진 컴파일·Play·Cook·패키징, GUI 클릭·입력, REA 바이너리 재구현, 262K 장시간 대화·실제 자동 압축·취소 복구, 새 PC·외부 네트워크·macOS/Linux 실기는 이번 결과에 포함하지 않습니다. 엔진 도구 연결과 지침은 게임 완성·그래픽 품질의 보장이 아닙니다. 한국어 지침과 UTF-8 적용도 모델의 모든 표현 선택을 완전히 보장하지 않습니다.

외부 클라이언트에는 실행기·설정·지침을 배포합니다. 서버 호환 수정은 서버의 Python 파일에 적용되는 기능이므로 서버를 새로 구성할 때 수정된 Strata/fork 소스도 복원해야 합니다. 클라이언트가 원격 서버 파일을 자동 변경하지 않습니다.
