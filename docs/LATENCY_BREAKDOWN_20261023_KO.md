## 실제 Strata SSE

| 65,467 | 21.312초 | 21.224초 | 0.083 / 0.073초 | 0.172 / 0.158초 |
| 259,445 | 87.290초 | 87.032초 | 0.143 / 0.154초 | 0.215 / 0.226초 |

- 9/9 조회 정답, 출력 length 종료 없음, 마지막 슬롯 idle 확인.
- warm은 입력을 그대로 반복한 경우다. 최초 구현과 두 차례 수정은 별도 `LONG_CONTEXT_EDITS_20261023_KO.md`에 기록했다. 이번 반복 조회를 복잡한 코드 편집 성능으로 해석하지 않는다.
- 약 260K cold의 첫 내용 지연 중 약 99.7%가 프리필이다. 동일 입력 warm은 259,438토큰을 재사용하고 7토큰만 새로 읽었다.
- 약 260K의 JSON 직렬화는 요청당 1.32~1.56ms, 약 600KB 전송이었다.
- HTTP 헤더/최초 SSE 패킷은 실제 내용보다 먼저 온다. 약 260K cold에서 헤더는 0.164초지만 실제 내용은 87.290초다. 빈 role 패킷을 첫 토큰으로 계산하지 않았다.
- 건강/슬롯/모델 조회 각 5회에서 전체 범위 약 0.8~25.7ms. `/slots`는 13.3~16.0ms였다. 이 수치에는 로컬 HTTP·스케줄링이 섞여 있다.
- 토큰 계산 API: 8K 21.7ms, 65K 60.0ms, 259K 179.4ms. 전체 프리필에 비해 작지만 매 단계 불필요한 중복 계산은 피할 가치가 있다.
- 단일 클라이언트 idle 상태에서 측정했다. 서버 큐 대기, 여러 사용자 경합, 외부 네트워크 RTT, High reasoning의 긴 생성은 이번 수치에 포함하지 않았다.

## 개선 판단

1. 우선순위는 cold 입력량과 문맥 재사용 유지다. 이미 적용된 필요한 파일 중심 읽기, 고정 system/tool prefix 유지 원칙과 일치한다. 캐시 때문에 최신 수정 요구를 누락해서는 안 된다.
2. CUA 도구 정의 선택적 로딩/중복 설명 정리는 후속 후보다. 현재 17개 자동 선택·좌표/입력 정책을 유지하면서 최종 모델 입력량과 정확도를 비교해야 한다. 이번에는 도구 목록·스키마·보안 정책을 축소하지 않았다.
3. PowerShell 기동 약 0.5초는 아주 짧은 도구 작업을 반복할 때 누적된다. 명령 병합은 독립 읽기에 유효하지만 수정·권한·의존 명령을 무작정 합치면 오류 경계가 흐려진다. preflight 삭제·상시 관리자 실행으로 줄이지 않았다.
4. 로컬 HTTP, ACP 완료 전달, CUA tools/list는 이번 조건에서 주요 병목이 아니었다. 임의 타임아웃 축소나 polling 증가를 적용할 근거가 없다.
5. 새 ACP 초기화/세션 생성은 최초 비용이다. 이 결과를 매 턴 발생하는 약 0.7초로 합산해서는 안 된다.

이번 변경은 재현 가능한 측정 도구와 테스트 타임라인이다. 런타임 성능 향상을 달성했다고 주장하지 않는다. 실측 이득과 정확도 유지가 확인된 런타임 변경은 없으므로 기본 설정은 유지했다.
