# Rider MCP 시작 대기 보완 (2026-10-23)

## 확인한 내용
- 실행 중 Rider와 OpenCode/CUA 프로세스가 존재한다.
- 최근 두 연결에는 완료 작업 기록이 없어 새 설정의 실제 Rider 완료시간은 확인하지 못했다.
- MCP startup barrier는 반복 루프만 시간 제한을 확인했다. mcp.list 또는 tool.list가 응답하지 않으면 await에서 제한 없이 정지할 수 있었다.

## 변경
- 두 조회를 같은 시작 제한의 남은 시간 안에서 기다린다.
- 시간 초과 시 settled:false와 조회 단계를 반환해 기존 경고 후 진행 경로로 돌아간다.
- 타이머는 정상 응답과 실패 모두에서 해제한다. 원래 조회는 취소 API가 없어 강제 취소하지 않으며 뒤늦은 응답으로 작업을 재실행하지 않는다.
- 기존 opt-in 15000ms 설정으로 로컬 immutable plugin 설치를 갱신했다. 실행 중 연결은 유지했다.

## 범위
실제 Rider UI 작업, GPU 속도 재측정 및 자동 테스트는 이번 변경에서 실행하지 않았다. 따라서 완료시간 개선 수치를 주장하지 않는다. 새 OpenCode 연결부터 변경이 적용된다.
