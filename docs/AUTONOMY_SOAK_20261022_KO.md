# 자율 코딩 경로 반복·지속 검사

## 판정

**PARTIAL.** 설치된 OpenCode 2.0.22와 CPU 모의 모델을 사용한 실제 경과 시간 검사다. 현재 GPU Strata 서버·Rider·사용자 프로젝트는 중단하거나 수정하지 않았다. 모의 모델이 정해진 도구 호출을 반환하므로 실제 모델의 코딩 판단·완성도·밤샘 작업이나 모든 상황의 무병목을 증명하지 않는다.

## 이번 수정

- 관리 서버의 무제한 로그 증가를 막았다. 기본 파일당 8MiB, 현재 파일+백업 3개로 32MiB까지 최신 로그를 보존한다. 이전 버전의 큰 로그도 최신 꼬리만 남긴다. 체크포인트와 진단 증거는 회전 대상이 아니다.
- 자식 출력은 별도 스레드에서 작은 조각으로 읽는다. 큰 한 줄도 전체를 메모리에 모으지 않으며 작은 출력도 프로세스 종료 전 기록한다. 로그 디스크 오류가 생겨도 출력 소비를 계속해 파이프 정체를 방지하고 오류를 노출한다. 종료 후 소유 출력 스레드까지 정리한다.
- 재시작 상태 조회에서 긴 체크포인트를 반복 전송하지 않는다. 체크포인트는 디스크에 보존하고 응답은 작업 ID·상태·취소·오류로 줄인다.

## 실제 경과 시간 결과

| 검사 | 시간 | 결과 |
|---|---:|---|
| 설치된 ACP 14종 시나리오 반복 | 602.255초 | 136회 통과, 실패 0 |
| 한 관리 프로세스에서 서버 교체·취소·상태 조회·로그 회전 | 361.757초 | 164회 통과: 재시작 132회, 취소 32회 |

ACP 시나리오는 재접속 10회, 일시 네트워크 실패 10회, 지속 네트워크 장애 10회, 인증 오류 10회, 셸 기한 초과 10회, 잘린/잘못된 JSON 복구 10회, 셸 취소 10회, 본문 수신 후 스트림 취소 10회, 완료 후 늦은 자동 재개 차단 10회, 모의 8192 컨텍스트 압축 10회, 32768/262144 압축 각 9회, 기록 없는 세션 9회, 외부 관리 서버 재시작 9회다. 파일 보존 시나리오는 무관한 파일 2048개를 포함한다.

ACP 실행기는 시나리오마다 격리된 새 OpenCode 프로세스/DB를 사용한다. 10분 동안 하나의 OpenCode 세션이 계속 코딩한 시험은 아니다. 컨텍스트 길이는 모의 예산이며 실제 262K 프리필이나 GPU 압축 품질을 측정하지 않았다.

단일 관리 프로세스에서는 상태를 15,600회 조회했고, 긴 체크포인트가 응답에 다시 섞이지 않는지 확인했다. 테스트용 로그 한도를 파일당 32KiB로 줄여 실제 회전을 반복했으며 최대 합계는 130,942바이트(한도 131,072바이트)였다. 기본 32MiB 한도를 실제로 채운 시험은 아니다. 정상 재시작 중앙값 2.594초는 CPU 모의 서버 값이며 Strata 모델 재로딩 시간으로 사용할 수 없다.

## 자원 관측

- ACP **테스트 실행기**: 핸들 155개, 스레드 1개 유지. 전용 메모리 18,206,720 → 19,492,864바이트. OpenCode 자식 프로세스의 메모리 수치는 아니다.
- 동일 서버 **관리 프로세스**: 핸들 218~220개, 스레드 3개. 전용 메모리 25,468,928 → 27,062,272바이트로 증가했으므로 메모리 누수가 전혀 없다고 단정하지 않는다. 큰 단조 핸들 누적은 해당 구간에서 관측되지 않았다.
- 종료 후 소유 자식 종료와 출력 스레드 정리를 확인했다. 종료 뒤 관리 테스트 프로세스의 스레드는 1개였다.

## 회귀 검사와 이력

- Python 기존 회귀 88개 중 87개 통과, Linux 전용 1개 건너뜀.
- 새 관리/출력 경로 검사 19개 통과: 실제 Windows BAT 공백 경로, 로그 한도, 이전 큰 로그, 실행 중 출력 도착, 디스크 실패에도 큰 출력 소비, 중복 요청, 취소 전달 순서, 준비·종료 실패 등.
- JavaScript 58개 통과: 실제 Node 프록시+가짜 CUA 드라이버의 무응답/종료/EOF 처리, 입력 범위·좌표·요청 타이머·출력 복구·서버 재시작 도구.
- 최종 관리 코드 통합 시도 `managed-restart-20261022-e`도 실제 설치된 ACP에서 자식 서버 교체와 같은 요청의 후속 생성·최종 종료를 확인했다.
- 지속 검사 중 수정한 코드가 하위 테스트에 순차 반영됐다. 6분 관리 프로세스 검사는 로그 회전/간결한 상태 응답을 도입한 버전이며, 이후 추가한 기존 큰 로그 정리는 별도 회귀 검사로 확인했다. 전체를 최종 소스로 고정한 밤샘 시험으로 표현하지 않는다.
- 기존 실패인 첫 본문 수신 전 취소 후 연결 종료 미확인 문제는 이번 수정으로 해결되지 않았다. 효과 없는 폴링·빈 응답 우회는 재도입하지 않았다. 이전 실패 기록은 `UNATTENDED_AGENT_REVIEW_KO.md`에 남겨 두었다.

## 증거와 재실행

원본은 `~/Strata-data/diagnostics/autonomy-soak-20261022-a/`와 `supervisor-soak-20261022-a/`의 `results.json`, 각 시나리오 로그·격리 DB·이벤트, `cleanup.json`에 있다. 시도별 파일을 덮어쓰지 않는다.
