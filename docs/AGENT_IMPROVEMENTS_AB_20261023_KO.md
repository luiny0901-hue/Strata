### 자동 발견은 실패 — 적용하지 않음

`load_gui_tools` 하나만 노출하고 GUI 도구를 먼저 불러오라고 지시했다. 모델은 이 도구 대신 아직 노출하지 않은 `get_window_state`를 바로 생성했다. 325 입력 토큰, 1.030초였지만 유효한 자동 로딩이 아니므로 실패다. 요청에 실제 PID나 입력을 전달하지 않았고 모델이 만든 미제공 도구 호출은 실행하지 않았다.

실패 시 해당 배치를 중단했다. 강제 tool_choice로 성공처럼 만들거나 같은 요청을 반복하지 않았다. 다음 배치에서는 독립적으로 예정돼 있던 두 번째 정적 도구 비교와 코드 수정 비교만 진행했다. 자동 발견의 두 번째 반복과 발견 뒤 실제 선택 단계는 미실행이다.

따라서 **이 모델에서 단순 프롬프트 기반의 CUA 자동 로딩은 바로 적용할 수 없다.** 향후 구현에는 제공된 도구 이름 검증, 안정적인 발견 경로, 새로운 GUI 작업으로의 전환, 도구 변경 시 캐시 손실을 포함한 통합 시험이 필요하다. 현재 자동 CUA 기능을 줄이거나 운영 도구 목록을 바꾸지 않았다.

## 결론 및 적용 상태

- 필요한 문맥 선별·고정 prefix 재사용·독립 읽기 묶기·부분 수정은 이 통제된 시험에서 속도와 정답 유지가 확인됐다. 기존 지침에도 이 방향이 들어 있어 중복 지침을 추가하지 않았다.
- 정적으로 선택한 CUA 조회 도구는 빨랐지만 자동 발견은 실패했다. 자동 선택·입력 정책을 유지하면서 로딩을 바꾸는 운영 개선은 아직 검증되지 않았다.
- 실제 OpenCode 압축 포함 장기 작업, Rider 표시, 복잡한 프로젝트 탐색, 실제 GUI 조작, 원격 PC RTT, High reasoning은 미검증이다.
- 런타임/글로벌 설정 변경과 푸시는 없다. 측정 도구, CPU 계약 테스트, 보고서만 추가했다.

사용자의 적용 요청에 따라 같은 날 기존 `STRATA_SESSION_RECOVERY_KO.md`의 네 조항을 수정했다. 관련 심볼/줄 범위부터 읽기, 기존 파일의 edit/patch 우선 및 단일 일치 검사, 같은 환경의 짧은 독립 조회를 한 셸 호출로 묶되 개별 오류 보존, 새 요청/도구 결과를 대화 뒤에 추가하고 고정 prefix의 불필요한 변경을 피하도록 구체화했다. 별도 중복 지침이나 자동 토큰 절삭기를 추가하지 않았다.
