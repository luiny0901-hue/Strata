## 원인과 적용

기존 서버는 257,034 입력 + 응답 예산 32,000이 전체 한도를 넘으면 API 400으로 거부했습니다. 실제 남은 응답 공간은 5,102토큰이었습니다. Claude는 같은 요청을 한 번 재시도한 뒤 ToolSearch 호환 경로를 해제했고, 도구 정의가 15개에서 251개로 늘면서 입력이 323,479까지 커졌습니다. 네 요청 모두 편집 도구 실행 전에 실패했습니다.

별도 에이전트 루프나 새 예산 계산기를 만들지 않았습니다. 이미 구현된 Strata의 `fit_max_tokens: true`를 다음 전용 프로필에 추가했습니다.

- 소스와 현재 설치의 ON/OFF `profiles/strata-unsloth-ud-iq4_xs-nvfp4fork-uncensored-{on,off}.json.template`.
- `%LOCALAPPDATA%/Strata/profiles`의 기존 ON/OFF 생성 JSON.

이 기능은 입력을 자르지 않습니다. 남은 공간보다 응답 상한이 클 때만 상한을 조정합니다. 입력 자체가 한도를 넘거나 답할 공간이 없으면 계속 오류를 반환합니다. 일반 서버 기본값과 다른 모델 프로필은 변경하지 않았습니다. OpenCode에도 같은 서버 프로필이 적용되지만 이번 실제 에이전트 재시험은 Claude Code 경로였습니다.

관리 재시작은 요청이 없는 것을 확인한 뒤 기존 supervisor로 한 번 실행했고 34.25초에 준비됐습니다. 최초 배포 검사는 실행 중 생성 프로필과 다음 실행용 템플릿 사이의 기존 `effort_position`, `vision.source_cache` 차이를 발견해 재시작 전에 멈췄습니다. 비교 때는 이 두 값을 기존 실행 상태로 임시 맞추고, 시작 직후 다음 실행용 템플릿의 원래 값을 복원했습니다. 네 운영 프로필의 영구 변경은 `fit_max_tokens` 한 필드뿐임을 원본 백업과 대조했습니다. 기존 OpenCode·Rider·Claude 설정과 개인 portable profile의 해시는 유지됐습니다.

프로필 두 개의 렌더링 검사, 기존 OpenAI/Anthropic 컨텍스트 경계 검사, Claude 연결·지침과 지연 도구 정의 검사를 합쳐 **38개가 통과**했습니다. 경계 검사는 가짜 엔진으로 입력 무손실·공간 없음 거부·한 토큰 응답을 확인하는 CPU 검사이며 실제 장기 GPU 안정성 증거와 구분합니다. C++·모델·Pack·GPU 설정은 변경하지 않았습니다.
