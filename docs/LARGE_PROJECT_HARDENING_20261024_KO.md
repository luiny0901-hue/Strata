# 대규모 프로그램·게임 개발 실행 경로 보완 — 2026-10-24

## 범위와 기존 기준

현재 OpenCode2.0.22·ACP·출력 복구·컨텍스트 압축·Windows 실행기와 설치 경로를 확인했다. 모듈 단일 소유권, 데이터/세이브 호환성, 엔진별 에셋 처리, 변경 묶음별 검증, 프로젝트 상태 정본은 기존 지침에 있어 반복 추가하지 않았다. 특정 대규모 제품을 완성하거나 상용 게임 품질을 검증한 결과는 아니다.

실제 수정은 출력 잘림 오류의 종료/재시도와 Windows 대용량 로그 미리보기다. 모델·GPU·출력 한도32,000·추론 기본High·압축 임계점·VRAM reserve는 변경하지 않는다. 네이티브 프로그램/게임 요구도 유지한다.

## 발견1: 반복 잘림이 정상 종료로 전달될 수 있음

출력이 연속으로 잘릴 때 처음 두 번은 작은 호출로 고치라는 복구 결과를 제공한다. 기존 세 번째 잘림 경로는 추가 복구를 멈추면서 일반 length 종료를 그대로 반환했다. 미완료 요청을 정상적인 종료로 취급할 여지가 있었다.

새 테스트2개가 기존 구현에서 실패한 기록은 `truncation-before-fix.log`다. 세 번째 이후에는 `STRATA_OUTPUT_RECOVERY_EXHAUSTED` 오류를 반환해 미완료임을 명시하고, 현재 응답의 미확인 도구 호출은 실행하지 않는다. 이미 이전 요청에서 저장된 파일은 보존한다. 정상 출력과 성공한 작은 호출 뒤에는 기존 복구 예산을 초기화한다.

## 발견2: 복구 소진 오류가 통신 오류로 재시도됨

최초 수정 후 실제 설치 OpenCode와 모의 서버를 연결하자 위 오류가 provider.transport로 분류돼 총6회 모델 요청이 발생했다(`exhausted-a.log`). 일반 네트워크 재시도가 추가 생성까지 반복한 것이다. 큰 출력에서는 불필요한 생성 비용과 대기 시간이 커질 수 있다.

기존 출력 복구 플러그인의 session retry hook에서 **해당 세션의 복구 예산이 소진됐고 자체 오류 표식이 있는 경우만** 추가 재시도를 차단했다. 일반 네트워크 오류·Retry-After·다른 세션·새 요청의 기본 재시도는 바꾸지 않는다. 별도 감독자나 자동 재개 루프를 추가하지 않았다.

최종 설치 OpenCode 시험(`exhausted-b.log`)은 다음을 확인했다:

- 잘린 응답3회 뒤 ACP 오류로 종료하고 추가 모델 호출 없음.
- 부분 파일 생성 없음, 이전 저장 파일 바이트 보존.
- 같은 세션의 명시적인 후속 요청이 작은 파일 쓰기1회와 최종 답변으로 정상 종료.

추가 호출6→3은 인위적으로 잘린 모의 응답의 비교이며 일반 코딩 시간50% 개선을 뜻하지 않는다. 모델이 두 차례 복구 지시에도 유효한 출력을 만들지 못하면 작업은 미완료 오류로 남는다. 이를 무한 생성이나 성공 보고로 바꾸지 않는다.

## 발견3: 긴 빌드 로그 앞부분의 오류가 미리보기에서 사라짐

Windows 실행기는 전체 stdout/stderr를 파일로 남기지만 24,000자 미리보기는 뒤쪽뿐이었다. 초기 빌드 오류 뒤에 다량의 출력이 쌓이면 원인 단서가 미리보기에서 보이지 않았다. 새 테스트2개에서 앞부분 표식이 사라지는 실패를 재현했다(`log-preview-before-fix.log`).

Windows 미리보기를 앞/뒤 각최대12,000자로 바꿨다. 중간 생략을 표시하고 전체 로그 경로·종료 코드·timeout/프로세스 정리 결과는 유지한다. 한글/이모지 경계가 깨지지 않도록 처리하며 큰 로그에서도 최대96,000바이트만 미리보기용으로 읽는다. 전체 로그 내용은 변환하지 않는다. 짧은 출력은 기존과 같다. 원인이 중간에 있으면 전체 로그를 범위 검색해야 하며 모든 오류를 미리보기에 담는 기능은 아니다.

원본300,000바이트 이상 stdout의 내용·앞 오류/마지막 표식·실패 종료 코드7, 긴 한글/이모지 로그의 원본 및 대체 문자 없음이 통과했다. 실행기 전체의 Windows 성공/오류/대기/timeout/Unicode 경로 검사도 통과했다. Linux/macOS 실행기의 미리보기는 이번 변경 대상이 아니며 Linux 실기는 미검증이다.

코딩 정본에는 기존 설계/호출부로 소유자를 확인하고 상태·불변 조건·검증을 한 모듈에 두며, 병렬 manager/store/supervisor·반복 설계 문서·순환 의존성·불필요한 추상화/분할을 피하는 규칙이 있다. 동일 지침을 다시 추가하지 않았다. 필요한 플랫폼 어댑터와 REA의 정확한 구버전 설정 이관 정의는 중복 기능으로 삭제하지 않았다.
