# OpenCode 도구 중복 실행 점검 — 2026-10-25

현재 Windows의 OpenCode 2.0.22에서 같은 명령을 서로 다른 도구 호출로 두 번 내보내면 실제 PowerShell도 두 번 실행됐다. 기존 취소·출력 잘림·재연결 보호만으로는 이 경우를 막지 않았다. 출력 복구 플러그인에 선택형 중복 실행 보호를 추가하고 Strata 코딩 에이전트 설정에서 활성화한다. Rider 자체가 요청을 중복 전송했다는 증거는 확인하지 못했다.

최근 OpenCode 16개 세션을 읽기 전용으로 점검했다. 검색 11회인 대화도 검색어가 모두 달랐다. 검색 횟수만으로 불필요한 중복으로 분류하지 않았으며 과거 로그의 반복 조회·명령도 상태 변경 여부를 확인하지 않고 오류로 단정하지 않았다. 진단 자료에는 원문 명령·검색 결과 대신 해시와 횟수를 기록했다.

## 동작

- 지원 경로는 설정한 Strata 공급자의 OpenAI 호환 `/chat/completions` SSE이다. 다른 공급자·확인하지 않은 전송 방식에는 실행 보호를 활성화하지 않는다. 범용 플러그인의 기본값은 끔이며 `toolDeduplication:true`로 켠다.
- 같은 사용자 요청·세션·에이전트의 동일 `shell`·`websearch`가 실행 중이면 두 번째 호출을 실행하지 않고 `TOOL_DUPLICATE_PENDING`으로 알린다. 호출 ID가 달라도 비교한다. 명령의 제한 시간만 달라진 경우도 같은 실행으로 본다.
- 동일 명령이 끝난 뒤10초, 성공한 동일 검색 뒤30초 안의 반복은 `TOOL_DUPLICATE_RECENT`로 알린다. 기다리는 시간을 추가하거나 과거 결과를 새 실행 성공으로 위장하지 않는다. 실패·취소·시간 초과로 부작용이 불확실한 명령도 즉시 맹목적으로 다시 실행하지 않는다.
- 필요한 순차 재실행·상태 확인·최신 검색은 도구 인자 `repeat:true`로 지정한다. 기존 명령·권한 검사는 다시 실행하며 이미 진행 중인 같은 작업은 이 인자로 우회하지 못한다. 사용자가 매번 새 승인을 해야 하는 방식은 아니다.
- 파일 변경 등 상태를 바꿀 수 있는 도구 뒤에는 완료 기록을 무효화한다. 새 사용자 요청과 압축 뒤에도 완료 기록을 재사용하지 않는다. 변경 후 같은 빌드·테스트와 새 요청의 같은 명령을 정상 실행한다. 진행 중인 실행은 압축만으로 중복 허용하지 않는다.
- Code Mode는 자식 도구가 부모의 호출 ID를 공유하고 내부 인자 디코더가 확장 인자를 제거한다. 정상적인 루프·상태 조회를 보존하기 위해 내부 순차 반복은 허용하고, 동일 작업이 동시에 겹치는 경우만 차단한다. 읽기·편집·쓰기·CUA 입력을 일괄 병합하지 않는다.
- OpenCode의 네이티브 인자 코덱은 변경하지 않는다. 기존 출력 복구의 검증된 SSE 인자 파서를 재사용해 `repeat`만 연결한다. 잘린 출력·잘못된 JSON·필터링·완료되지 않은 스트림은 재실행 표시를 등록하지 않는다. 별도 스트림 파서·서비스·모델 호출은 추가하지 않았다.
- 기록은 메모리에 세션 최대64개, 완료 기록은 세션당64개, 인자 연결 기록은 각각256개로 제한한다. 명령 본문·검색 결과를 보관하지 않는다. 프로세스 재시작을 가로지르는 영구 실행 보장은 제공하지 않는다.

## 설치된 OpenCode에서의 비교

격리된 ACP 설정·DB와 스크립트 응답 모델을 사용했다. 터미널은 실제 제한 시간 PowerShell 프로세스이며 검색은 호출 횟수를 기록하는 시험용 검색 백엔드다.

| 시나리오 | 보호 끔 | 보호 켬 | 판정 |
| --- | ---: | ---: | --- |
| 동시에 같은 터미널 명령 | 실제 실행2회 | 실제 실행1회 | PASS |
| 완료 직후 같은 터미널 명령 | 실제 실행2회 | 실제 실행1회 | PASS |
| 동시에 같은 관리자 실행 명령 | 실행기 진입2회 | 실행기 진입1회 | PASS; 실제 UAC 실행은 양쪽0회 |
| 완료 직후 같은 관리자 실행 명령 | 실행기 진입2회 | 실행기 진입1회 | PASS; 실제 UAC 실행은 양쪽0회 |
| 동시에 같은 검색 | 백엔드2회 | 백엔드1회 | PASS |
| 완료 직후 같은 검색 | 백엔드2회 | 백엔드1회 | PASS |

UAC 사례는 기존 PowerShell 사전 검사의 `BLOCKED_UAC` 거부를 사용했다. 실제 관리자 확인창을 띄우거나 승인하지 않았으며 UAC 우회 검증이 아니다.

정상 반복7개 사례도 PASS: 의도적 명령 재실행, 소스 변경 후 재실행, 다음 사용자 요청, 최신 검색, 다른 검색어, 검색 실패 후 재시도, Code Mode의 순차 호출. 의도적 실행은 원래 호출 횟수를 보존했다. 추가로 기존8K·262K 반복 자동 압축, 취소, 재연결, 늦은 재개5개 사례가 PASS했다. 합계24개 통합 시나리오다. 이는 실제262K GPU 추론 측정이나 Rider 버튼 조작 검증이 아니다.

## 회귀 검사와 실패 이력

현재 소스 기준 Node57개, Python52개 검사를 통과했다.

```powershell
node --test tools/test_tool_dedup.mjs tools/test_output_recovery.mjs tools/test_task_stream.mjs tools/cua-driver/opencode-request-lifecycle.test.mjs
python -X utf8 -m unittest tools.test_opencode_runtime_assets tools.test_remote_agent_client tools.test_opencode_session_recovery tools.test_configure_opencode_cua_automation
```

실패·재시도 자료는 삭제하지 않았다. 진단 폴더는 `C:\Users\luiny\Strata-data\diagnostics\duplicate-tool-review-20261025`다.

1. 최초 설치형 검사에서 네이티브 입력이 JSON 스키마가 아닌 코덱이어서 보호가 적용되지 않았다. 스키마를 교체하지 않고 기존 코덱을 보존하도록 수정했다. `shell-parallel-on`, `search-sequential-on`, `code-mode-on`의 실패와 `*-on-b` 재검사를 보존했다.
2. Code Mode의 확장 인자 제거로 정상 순차 검색까지 줄어드는 실패가 있었다. 내부 순차 신선도 예외를 두고 `code-mode-on-c`를 통과했다.
3. 최초24개 행렬 `matrix.json`은22개 통과·2개 실패였다. 직접 도구 호출에서도 네이티브 디코더가 `repeat`를 제거하는 원인을 확인하고 기존 SSE 확정 인자 파서에 연결했다.
4. 연결 보완 중 빈 기록 비교 오류로 Node 검사가 멈춘 `node-bridge-a.log`는 해당 시험 프로세스만 종료하고 보존했다. 오류를 수정한 `node-bridge-b.log`는51개 통과했다. 앞선 `*-on-d` 성공만으로 보호 자체가 유효하다고 판단하지 않고 전체 행렬을 다시 실행했다.
5. `matrix-bridge.json`, `matrix-final2.json`과 공급자 경로 제한을 추가한 최종 `matrix-route.json`은 각각24개 모두 통과했다. 초기 `node-final.log`는 CUA 검사 파일명 오기로52개만 실행됐다. 올바른 파일을 지정한 `node-final-cua.log`는56개, 공급자 경로 검사를 추가한 `node-route-final.log`는57개 통과했다.

현재 PC의 설정·배포 파일 대조 결과는 같은 진단 폴더의 `deployment.json`, `package-verification.json`에 기록했다. 일반·개인 ZIP 각각 Python52개 검사, revision20 격리 설치, 출력 플러그인 모듈 로딩과 CRC 검사를 통과했다. 다른 ZIP 항목과 개인 프로필은 바이트 대조로 보존을 확인했다. API 키·명령 원문은 이 보고서에 포함하지 않는다.

## 적용과 한계

현재 PC의 기존 출력 복구 플러그인을 해시 버전 `ef64caf477195d9aeee9a804481daa3d4f182f2d02a04347488e2b33640d1b6e`로 등록하고 옵션을 활성화했다. 모델·추론·압축·권한·MCP·CUA/REA 설정, Rider ACP 등록과 개인 프로필은 보존했다. Strata 엔진은 재시작하지 않았다. 현재 실행 중인 OpenCode/ACP 프로세스는 변경 전 시작되었으므로 작업을 마친 뒤 OpenCode 연결을 다시 시작해야 한다. Rider 자체의 업데이트나 재설치는 필요하지 않다.

재설치·외부 PC용 설치기는 revision20이다. 최신 클라이언트 ZIP을 풀고 START-AGENT의 연결 설정 갱신을 실행하면 같은 보호를 설치한다. 일반·개인 ZIP을 함께 갱신하며 개인 프로필은 그대로 보존한다.

다른 검색어·다른 명령 표현을 같은 의도로 추론해 합치지는 않는다. Code Mode 내부의 순차 중복, 임의 MCP 도구, 실제 검색 제공자 장애, 실제 UAC 확인 지연·Rider GUI의 재전송은 이번 시험에서 새로 검증하지 않았다. 모든 모델 행동에서 중복 작업이 사라졌다는 보장은 아니다.
