# Claude Code 전문 개발·장기 유지보수 지침 점검

2026-10-25, 기존 개발 지침과 Claude Code 프로필을 비교했습니다. 기본 품질·언어·엔진·장기 개발 원칙은 이미 있었지만, 현재 코드·검증 결과 재사용과 중복 방지의 구체 규칙, MCP/컨텍스트, 압축 후 재개, 최신 기술 근거, 전문 데스크톱 상세 지침이 일부 빠져 있었습니다. 누락을 보완하고 현재 설치와 클라이언트 배포본에 반영했습니다.

지침 생성·프로젝트 판별은 `tools/claude_code_guidance.py` 한 모듈이 담당하고, 공통 설정·인증·실행·MCP 연결은 `tools/claude_opencodex_client.py`가 담당합니다. 지침 본문을 별도로 수작업 복제하지 않습니다. 필수 정본 절이 없어지면 조용히 누락하지 않고 오류를 표시합니다. 일반 CLAUDE.md는 기존 8,411자/92줄에서 약 13,000자/133줄로 늘었으며, 누락된 공통 규칙을 포함하되 상세 지침과 별도 모델 호출은 추가하지 않았습니다.

## 실제 작업 검증

실제 Windows Claude Code 2.1.308 → Strata의 격리된 검증 프로젝트에서 다음을 확인했습니다. 서버·GPU·모델·기존 사용자 앱 설정은 변경하지 않았습니다.

1. **새 대화의 유지보수**: 기존 저장 모듈, 검증 모듈, 호출자, 테스트와 상태 문서가 있는 게임 저장 로직 프로젝트에 관련 없는 파일 60개를 추가했습니다. 채팅 기록 없이 README/STATE를 읽어 미완료 단계만 진행하게 했습니다. 기존 검증 소유자를 재사용했고, 변경은 `storage.py`와 기존 STATE뿐이었습니다. 8개 검사와 별도 재실행이 통과했으며, 개발자 파일·다른 모듈·검사 파일·관련 없는 파일은 해시가 유지됐습니다. 43.60초가 걸렸습니다.
2. **실제 수동 압축**: 같은 Claude 세션에서 `/compact`를 실행했습니다. 터미널의 완료 표시와 세션 파일의 `compact_boundary`를 함께 확인했습니다. Claude 기록상 28,649 → 9,169토큰, 26.87초였습니다. 이는 작은 대화의 수동 압축 기록이며 262K 자동 압축 처리량이 아닙니다.
3. **압축 뒤 요구 변경**: 이전에는 거부했던 중복 아이템을 합산하도록 요청하되 음수/불리언은 합산 전에 거부하도록 했습니다. 기존 검증 함수를 재사용하고 영향을 받는 검사만 수정·보완했습니다. 9개 검사와 다른 키/값을 쓴 독립 검사가 통과했습니다. 변경은 저장 모듈·관련 검사·기존 STATE 3개뿐이었습니다. 40.57초가 걸렸습니다.
4. **채팅 기록 없는 상태 설명**: 다른 세션 ID의 새 대화에서 README/STATE만 읽어 완료·남은 범위를 설명했습니다. Read 2회, 파일 변경과 검증 재실행은 없었습니다. 14.67초가 걸렸습니다.
5. **전문 프로그램 설계만 요청**: WPF 메타데이터와 README만 있는 이미지 편집기 검토 프로젝트에서 문서/명령/실행취소/UI/렌더/작업/파일 소유 경계를 설명했습니다. 프로젝트 파일은 바뀌지 않았고 구현·설치·빌드는 하지 않았습니다. 첫 실행 25.56초, 보완 후 같은 요청 23.12초였습니다. 캐시·생성 결과가 달라 속도 향상 수치로 해석하지 않습니다.

설계 시험에서는 처음에 Glob 2회·Read 2회 뒤 읽기 전용 PowerShell 파일 목록 조회가 추가됐습니다. 알려진 경로를 직접 읽고 같은 목적의 목록 조회를 반복하지 않도록 안내를 보완했습니다. 한 재검사에서는 PowerShell 조회가 사라졌지만 Glob 2회는 남았습니다. 모든 중복 조회가 기술적으로 차단됐다고 주장하지 않습니다.

관련 Python 검사 33개가 통과했습니다. 새 전문 지침 검사에는 정본 절 누락 방지, 기존 본문 재사용, 데스크톱/CLI/엔진 구분, Git 경계, 큰/잘못된 메타데이터, compact 후 범위 상기와 무변경 확인이 포함됩니다.

## 실패 기록과 보존

- 최초 18개 검사 중 하나는 새 desktop 지침 파일을 아직 기대하지 않아 실패했습니다. 자산 계약을 갱신하고 본문 재사용·범위 검사를 추가한 후 관련 검사 33개가 통과했습니다.
- 처음 검증용 Python을 준비한 하네스는 자식 검사의 cp949 출력을 UTF-8로 읽다가 실패했습니다. 실제 Claude 작업 시작 전의 하네스 오류이며 로그를 보존하고 검사 프로세스를 명시적인 UTF-8로 다시 실행했습니다. 제품 훅의 기존 UTF-8 설정은 유지했습니다.
- 설계 범위 검사는 처음에 모든 셸 호출을 금지해 읽기 전용 목록 조회도 실패로 판정했습니다. 실제 명령과 파일 보존을 확인하는 독립 검사로 바로잡았습니다. 독립 검사의 Windows 줄바꿈 기대값도 원래 생성 방식에 맞춰 확인했습니다. 원래 실패 로그는 지우지 않았습니다.
- 실제 에이전트는 검증 프로젝트에서 Git의 `dubious ownership` 오류를 만났습니다. 전역 Git 신뢰 설정을 바꾸지 않고 실제 파일·검사로 진행했으며 최종 보고에 제약을 남겼습니다.
