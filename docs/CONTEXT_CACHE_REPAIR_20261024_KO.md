## 확인한 동작

현재 모델 한도는 262,144이며 자동 압축은 약 196,608에서 시작하고 최근 기록 보존 설정은 12,000이다. OpenCode 2.0.22 코어의 계산은 캐시 재사용 토큰도 컨텍스트 점유에 포함한다. 캐시는 입력 처리 비용을 줄이지만 문맥 한도를 늘리지 않는다. 완료된 체크포인트 직후에는 요청을 먼저 재구성하며 바로 다시 압축하지 않는다. 다음 압축은 기존 체크포인트를 갱신한다.

최근 기록의 12,000은 정확한 잘라내기 한도가 아니다. 코어가 사용자 메시지와 이어진 도구 호출·결과를 함께 보존하므로 한 번의 큰 작업 묶음은 이를 넘을 수 있다. 이 경계를 임의로 자르거나 기록을 삭제하지 않았다. 과거의 일괄 조기 압축 비교에서는 요약 비용으로 느려진 사례가 있어 임계점·보존량은 유지했다.

## 발견과 수정

기존 플러그인은 압축 전용 지침을 시스템 앞부분에 추가했다. 일반 요청에서 보완한 도구 설명·스키마도 압축에서는 달랐다. 실제 설치 OpenCode의 요청을 캡처해 두 차이를 모두 확인했다. 이 때문에 긴 대화의 입력 캐시가 압축 요청에서 깨질 수 있었다.

선택 옵션 `cacheStableCompaction=true`를 두 플러그인에 함께 적용한다.

- 일반 요청과 압축 요청이 같은 기존 지침·도구 설명 준비 함수를 재사용한다.
- 압축 전용 보존 지침은 기록 뒤, 코어 요약 프롬프트 앞의 내부 메시지에 한 번만 붙인다.
- 사용자/도구 기록, 타사 지침, 요약 형식, 요청 의도·권한 경계는 보존한다.
- 플러그인 순서를 바꾸거나 같은 이벤트를 재사용해도 소유한 요약 지침은 하나만 남긴다.
- 옵션이 꺼진 기존 경로는 유지한다. 정상 답변의 추론 수준, 출력 한도, 자동 압축 기준은 바꾸지 않는다.

두 플러그인은 각각 기존 책임을 유지하며 새 압축기나 별도 상태 저장소를 만들지 않았다. 모델 자체의 요약 비용을 없애는 기능은 아니다.
