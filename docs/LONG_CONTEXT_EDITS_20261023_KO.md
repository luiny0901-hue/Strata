# 262K 상한에서 구현 후 수정 2회 측정

2026-10-23, 실행 중인 Strata ON 서버에서 단일 대화로 측정했다. 서버 시작·재설정·재시도 없이 완료했다.

## 조건과 범위

- 최대 문맥 262,144, 실제 입력 259,630~260,159토큰. 출력과 후속 이력 공간을 남겼다.
- 모델 `qwen3.8-flash-next-unsloth-ud-iq4_xs`, 실행 중인 NVFP4 fork / RTX 3090 Ti 서버.
- 직접 Strata Chat Completions API + 격리된 `save_file` 도구 루프. 실제 OpenCode/ACP/Rider 경로가 아니다.
- 이전 컨텍스트 전략 실험과 동일한 실행 서버를 사용했다. 이번 실행은 health/model/context 확인이며 전체 모델 파일 해시 재검증은 아니다.
- 합성 긴 로그를 배경 문맥으로 넣고, 작은 순수 계산 함수를 구현 → 수량 할인 추가 → 배송비 및 0수량 예외 추가했다.
- 각 단계는 파일 저장 도구 호출과 완료 응답으로 구성된 모델 호출 2회. 같은 system/tools/messages 이력을 유지했다. 압축·이력 절삭 없음.
- 실험에만 reasoning_effort=none, temperature=0, 호출당 최대 출력 512를 사용했다. 사용자 High 설정은 변경하지 않았다.
- 모델이 생성한 코드는 import/call/loop/attribute 등을 허용하지 않는 제한 AST 확인 후 빈 builtins 환경에서 산술 검증했다. 사용자 프로젝트는 수정하지 않았다.
- 긴 입력 생성/토큰 수 맞춤 시간은 아래 작업 시간에서 제외했다. HTTP는 비스트리밍이므로 첫 토큰 도착 시간(TTFT)은 측정하지 않았다.

## 판단

이 표본의 주요 병목은 최초 긴 문맥의 cold 프리필이다. 초기 구현 시간의 약 98.7%를 프리필이 차지했다. 후속 두 수정은 같은 긴 문맥을 대부분 재사용했고, 전체 262K를 다시 읽는 현상은 관측되지 않았다. 후속 수정에서는 짧은 생성 시간이 프리필보다 컸다.

실제 OpenCode 설정은 추정 사용량 196,608토큰 부근에서 자동 압축한다. 따라서 이 무압축 직접 API 결과를 OpenCode의 262K 압축·도구 검색·Rider 표시·복잡한 다중 파일 구현 성능으로 확장할 수 없다. 문맥 재사용을 깨는 이력 변경, 다른 클라이언트 요청, 압축 또는 서버 재시작 뒤의 비용도 이번 1회에서 측정하지 않았다. 이 결과만으로 압축 임계값이나 모델 기본 설정을 변경하지 않았다.
