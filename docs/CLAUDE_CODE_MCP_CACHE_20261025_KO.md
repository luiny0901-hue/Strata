# Claude Code의 MCP 도구 검색 뒤 재계산 지연 개선

2026-10-25, 앞서 적용한 `effort_position: end`, `fit_max_tokens`, 축약 기본 프롬프트와 재시도 설정을 유지한 채 추가 병목을 조사했습니다. 실제 Claude Code 2.1.308 → Strata NVFP4 fork → RTX 3090 Ti의 ON 프로필에서 도구 검색 직후 긴 입력을 다시 읽는 병목을 재현하고 개선했습니다. 모델은 기존 `qwen3.8-flash-next-unsloth-ud-iq4_xs`이며 컨텍스트 262,144·출력 상한 32,000·GPU reserve 448 MiB는 유지했습니다.

## 원인

Claude의 ToolSearch는 처음부터 전체 CUA·REA 정의를 넣지 않고 필요한 두 도구를 검색했습니다. 기존 Strata 변환은 검색된 정의를 입력 앞의 도구 목록에 추가했습니다. 그 결과 앞부분이 바뀌어, 실제 새 기준 시험에서 검색 직후 **29,923토큰 전체를 다시 읽고** 첫 콘텐츠까지 11.58초가 걸렸습니다. 다음 일반 요청은 캐시를 다시 사용했습니다. 도구가 실행을 기다리느라 생긴 지연과 구분합니다.

## 변경

새 선택 기능 `anthropic_tool_cache: true`를 추가했습니다. 일반 서버 기본값은 꺼져 있고, 사용자 전용 ON/OFF 템플릿과 현재 생성 프로필에만 켰습니다.

- 기존 eager 도구는 앞부분에 유지합니다. 검색된 deferred 도구의 정의는 해당 정의를 처음 참조한 실제 `tool_reference` 결과 옆에 넣습니다.
- 출력 파서와 강제 도구 선택·인자 검증에는 기존 전체 선택 도구 목록을 전달합니다. 스키마나 required 인자 검증을 제거하지 않습니다.
- 같은 도구를 다시 검색해도 정의를 중복 삽입하지 않습니다. 현재 요청에서 정의가 갱신·제거되면 그 내용이 반영되며 별도 세션 캐시를 만들지 않습니다.
- 압축으로 검색 결과가 사라지고 이전 tool_use만 남았다면 해당 정의를 기존 앞부분에 둡니다. eager 도구가 없거나 이름이 중복되는 모호한 경우도 기존 형식을 사용합니다.
- 텍스트와 이미지를 보존하고 검색하지 않은 정의는 계속 제외합니다. 입력을 자르지 않습니다. 정의가 이동하면서 설명 문구 때문에 전체 입력 수는 조금 늘 수 있습니다.
- `/v1/messages/count_tokens`와 실제 생성에 같은 배치를 적용합니다. OpenAI/Responses 경로는 이 선택 기능을 사용하지 않습니다.

정본은 `serve/frontend.py`의 순수 프롬프트 투영 함수이며, `serve/server.py`의 Anthropic 두 경로에서만 사용합니다. 기존 에이전트 루프·MCP 실행·권한·모델·엔진은 바꾸지 않았습니다.
