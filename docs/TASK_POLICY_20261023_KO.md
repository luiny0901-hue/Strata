- 웹툰: 회차·컷 번호·세로 스크롤 호흡·화면 연출·대사/지문 구분.
- 출판 만화: 페이지·컷 배치·읽는 방향·말풍선 순서 구분. 원고/콘티와 작화 산출물 구분.
- 게임 스토리: 퀘스트·선택지·분기 조건·상태 변화·대사 ID·엔딩 연결 보존. 기존 변수/키는 유지하고 스토리 작성 요청만으로 게임 코드를 구현하지 않음.
- 애니메이션: 일본 애니메이션을 기본 참고 기준으로 TV/극장판·장르·요청한 참고 작품에 맞춰 회차·시퀀스·씬, 동작·표정·타이밍·콘티 관리. 특정 작품의 스타일을 모든 작업에 강제하는 설정은 아니다.
- 영화: 요청한 시나리오 형식·장면 번호·장소/시간·행동/대사·인과관계·예상 러닝타임 관리. 원고/콘티를 실제 작화·촬영·애니메이션 제작 완료로 보고하지 않음.
- 압축: 관련 작업의 회차/페이지/컷, 대사 순서, 분기 조건과 상태·엔딩 연결도 필요한 경우 보존.

## 적용 방식

- 기본은 코딩·웹 개발이다. 요청한 산출물과 동작을 함께 판단한다. 웹소설 사이트·독자 앱·게시판 오류는 소프트웨어 작업이고 질문·인용·부정은 집필 허가가 아니다.
- 실제 원고 작성·이어쓰기·퇴고에는 언어·분량·시점·문체·인물·말투·세계관·시간 순서·복선 보존, 장/장면 저장, 마지막 저장 위치와 미완료 범위 확인을 적용한다. 짧은 글에 설정집이나 빌드를 강제하지 않는다.
- 혼합 요청은 원고와 코드의 산출물/완료 조건을 구분한다. 새 요청에서 코딩으로 돌아오면 창작 절차를 적용하지 않는다.
- 압축 지침도 현재 작업 유형을 보존하고, 창작 작업에 해당할 때만 원고 경로·확정 인물 관계·시점·문체·시간 순서·미회수 복선·완료/미완료 장과 저장 위치를 남기도록 한다.

긴 창작 지침을 별도 도구로 자동 로딩하는 시제품은 오분류 때문에 폐기했다. 최종 방식은 **502자의 짧은 조건부 지침이 고정 system prefix에 들어가고 모델이 현재 요청에 해당하는 규칙을 적용**하는 방식이다. 문맥에서 조건부 문장 자체를 완전히 제거하는 동적 로더는 아니다. 따라서 코딩 문맥에도 이 작은 문단의 토큰 비용은 있다. 고정 도구 목록이나 prefix를 작업마다 재배열하지 않는다.

현재 토크나이저의 한 줄 요청 count_tokens 비교에서 기존 system은 5,972토큰, 조건부 문단 추가 후 6,240토큰으로 **268토큰 추가**였다. 별도 분류 추론·지침 도구 호출·파일 조회는 추가하지 않는다. 전체 완료시간 개선율을 측정한 결과는 아니다.

실패를 성공으로 덮어쓰지 않았다. 마지막 시제품 소스와 실행기는 같은 c 폴더의 `rejected-loader-index.js`, `rejected-loader-test.py`에 보존했다. 시제품 도구와 긴 지침은 최종 플러그인/설정에서 제거했다. 최종 시험은 HTML 예시를 li 1개/3줄로 한정하고, 도구 호출 여부 대신 실제 결과를 검사하도록 별도 구성했다. 두 시험의 시간이나 통과율을 동일 조건의 성능 비교로 쓰지 않는다.

편집 도중 patch 머리말 누락과 README의 잘못된 문맥으로 두 번 patch 검증이 실패했다. 해당 파일을 부분 변경하지 않았고 올바른 패치/별도 보고서로 진행했다.
