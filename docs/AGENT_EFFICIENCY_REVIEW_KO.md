# 코딩 에이전트 구성 점검 (2026-10-22)

범위는 OpenCode 설정·지침, ACP/스트림 복구 플러그인, 클라이언트 설치와 컨텍스트 선언,
기존 CUA/REA·제한 시간 실행기의 관련 로컬 검사다. 모든 실제 프로젝트·플랫폼에서
무인 작업 완료를 보증하는 검사는 아니다.

## 변경

- 설치된 코딩 지침이 있을 때 출력 복구 플러그인의 같은 코딩 설명을 추가하지 않는다.
  지침이 없는 단독 설치에는 기존 설명을 유지한다. write 호출 크기 제한도 유지한다.
- ACP context 훅을 여러 번 적용해도 완료 지침과 도구 설명을 누적하지 않는다.
- 두 플러그인의 등록 순서와 반복 압축에 관계없이 자체 압축 지침은 하나로 통합한다.
  제삼자 지침은 지우지 않는다.
- SSE 구분자가 오지 않거나 단일 이벤트가 과도하게 클 때 8,388,608 문자 제한으로 중단한다.
  확인 전 도구 호출은 실행하지 않는다. 정상 텍스트/도구 스트림, 취소, 잘림 복구를 보존한다.
- 도구 인자 조각은 배열에 모은 뒤 검증 때 합친다. 처리 속도 향상은 주장하지 않는다.
- 원격 서버가 유효한 4096 이상 정수 max_context를 보고하지 않으면 262K로 추정하지 않고
  설정을 중단한다. 4096~262144 여러 크기의 출력 상한과 압축 여유를 오프라인 검사했다.
- 질문에 필요한 읽기 전용 확인과 실제 상태 변경을 구분하고, 무조건 도구 없이 되묻는 지침을 수정했다.
  버전별 공식 근거는 필요한 부분만 확인·재사용하며 임의 업그레이드하지 않도록 보완했다.
- 클라이언트 문서의 '전역 설정을 수정하지 않는다'는 문구에서 REA 등록의 백업/변경 동작을 명확히 했다.

## 로컬 적용

이 PC 전역 OpenCode 지침이 알려진 이전 배포본과 일치함을 확인한 뒤 백업했다.
모델·provider·API 키·ACP 항목은 보존하고 새 해시 버전 플러그인 참조와 한국어 지침을 갱신했다.
진행 중인 작업이 끝난 뒤 OpenCode/ACP를 다시 시작해야 활성화된다. 다른 PC는 갱신된
소스를 받은 뒤 setup을 다시 실행해야 한다. 현재 변경은 미커밋·미푸시 상태다.

## 추가 점검: 불필요한 반복 비용

- Bash 명령 실행기는 완료 여부를 1초 간격으로 확인하던 루프 대신 직접 wait한다.
  진행 보고는 별도 monitor가 담당하고, 명령 종료·취소 때 monitor와 sleep 자식을 정리한다.
  짧은 명령을 다음 진행 보고 시각까지 기다리지 않는다. 제한 시간과 종료 코드는 유지한다.
- CUA PNG 크기 확인은 전체 base64 이미지 대신 처음 32문자(헤더 24바이트)만 디코딩한다.
  원본 이미지를 잘라 보내거나 해상도를 낮추지 않는다. 잘못된 이미지 데이터는 좌표 근거로 인정하지 않는다.
- 클라이언트 재설정 때 내용이 같은 일반 파일은 임시 파일 생성·fsync·교체를 생략한다.
  POSIX 권한이 다르면 권한은 바로잡으며, 바뀐 파일의 백업과 비밀 키의 권한 설정은 유지한다.
  심볼릭 링크는 동일 내용 생략 대상으로 삼지 않는다.

Git Bash에서 `printf OK` 실행·회수 측정(준비 1회 제외, 동일 명령 3회 중앙값):

## 추가 품질 검토: 편의상 오류를 넘기는 경로

CUA 프록시의 넓은 catch가 잘못된 드라이버 출력을 원문 그대로 전달하던 처리를 제거했다.
JSON-RPC 객체·버전·ID·응답 형식을 확인하고 비정상 응답은 명시적 오류와 연결 정리로 처리한다.
`null` 등 객체가 아닌 JSON도 처리 중 예외로 누락하지 않는다.

요청 ID 없는 `tools/call`은 기존 정책 검사 분기를 건너뛸 수 있어 전달 전에 차단했다.
중복 요청 ID도 같은 ID에 정상/오류 응답이 뒤섞이지 않도록 연결 오류로 종료한다.
과다 대기 요청의 용량 제한은 별도 오류로 유지한다. GUI 동작을 자동 재전송하지 않는다.

실제 Node 프록시와 가짜 드라이버로 잘못된 응답·객체 아닌 JSON·ID 없는 도구 호출의
실패 경로를 추가 검사했다. ID 없는 호출은 드라이버에 전달되지 않았다.
관련 Python 36개와 JavaScript 51개, ACP guard 검사 통과. 실제 GUI·모델 성능 검사는 아니다.

공통 작업 지침에는 예외 삼키기·가짜 성공·무효 폴링·전체 재작성·중복 상태 저장소를 편의상
선택하지 않고, 기존 구조와 정확성·성능·복구 비용을 기준으로 판단하도록 한 항목을 추가했다.
모든 변경마다 대안 보고서나 새 프레임워크를 만드는 지침은 추가하지 않았다.
검토한 이전 설치본과의 diff를 확인하고 백업 후 이 PC의 프록시와 공통 지침에도 적용했다.
첫 가시 응답 전 조기 취소의 연결 종료 문제는 별도 미해결 항목으로 유지한다.

## 추가 구조 점검

기존의 단일 기능 소유자·설계 정본·순환 의존성 방지 규칙을 유지하고, 상태·불변 조건·한도·검증
규칙의 소유자도 명시했다. 새 계층·의존성은 실제 공유 계약이나 독립적인 변경 이유가 있을 때만
추가하고 서로 다른 정책을 코드 모양만으로 합치지 않도록 보완했다. 교체 시 호출부·설정·데이터
호환성과 기존 경로 사용 여부를 확인하며, 작은 수정에서 전체 재설계를 요구하지 않는다.
성능 검토는 관련 경로의 N+1·반복 I/O·할당·무제한 큐/캐시·구독/태스크 수명에 한정한다.

실제 코드에서는 CUA 요청 용량 한도가 proxy와 lifecycle에 중복 정의돼 있었다.
한도 판정을 RequestDeadlines.atCapacity 하나로 옮겼고, proxy와 최종 등록 검사가 이를 재사용한다.
용량 초과 차단·완료 후 자리 반환·연결 종료 정리를 검사했다.
관련 Python 31개와 실제 Node/모의 드라이버를 사용하는 JavaScript 10개가 통과했다.
이 PC 설치본도 이전 소스와 같음을 확인한 뒤 백업 후 적용했다. OpenCode/ACP 새 세션에서 반영된다.
향후 모든 프로젝트의 중복·성능 문제를 자동 증명하는 정적 분석기나 실제 게임/모델 검증은 아니다.

## 설계·구현 판단 보완

기존 품질 규칙에 도메인 규칙·입출력 계약·데이터 흐름·부분 실패·취소/재시작·호환성·동시성·자원
수명 검토를 통합했다. 영향이 큰 선택에서 실제 대안과 근거를 비교하며 작은 수정에는 별도 설계
보고서나 전체 재검토를 요구하지 않는다. 이 PC 지침에도 이전 내용 일치 확인과 백업 후 적용했다.

실제 수정으로 엔진 프로젝트 지침 설치기의 exists-then-copy 경쟁 조건을 없앴다.

부재 확인이 오래된 상황을 모의해 기존 지침 보존을 검사했다. Python 관련 검사 34개 통과.
이 결과는 지침 배포·설치기 동작의 근거이며 모든 분야의 전문가 판단이나 출시 제품 품질 보장은 아니다.
