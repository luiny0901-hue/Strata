# Rider 반복 확인·도구 대기 개선

## 적용

- 기존 검증 지침을 수정해 완료 조건을 충족하는 최소 검사 묶음을 사용하도록 했다. 내용 확인과 같은 파일의 셸 재조회, 수정 시각 조회와 내용 재조회가 연달아 생기는 경로를 줄인다. 정확한 바이트·인코딩·줄바꿈이 요구되면 한 검사에서 함께 확인한다. 실패·외부 변경·불확실한 부작용의 재확인은 유지한다.
- read/edit를 우선하고 독립 조회는 같은 모델 응답에서 병렬 요청하도록 했다. 셸이 필요한 짧은 독립 조회는 묶되 쓰기·승인·의존 작업은 순서를 유지한다. 별도 분류 모델이나 요청마다 실행되는 추가 검사 도구는 넣지 않았다.
- 설치기에 선택 옵션 `--bounded-mcp-timeouts`를 추가하고 현재 PC에 적용했다. 명시적인 전역/서버 execution 설정이 없을 때 CUA 180000ms, REA 1800000ms를 설정한다. 기존 명시값은 유지하며 옵션 없는 설치 경로는 변경하지 않는다.
- 현재 PC의 모델·추론 수준·출력 한도·압축·권한 설정은 보존했다. 실제 설정 비교에서 변경은 두 MCP 실행 제한뿐이었다. 지침과 설정은 백업 후 설치했다.

3분/30분은 무응답 대기의 운영 상한이며 성능 측정으로 얻은 최적값은 아니다. REA 단일 분석이 30분 이상 필요하면 execution을 명시적으로 늘려야 한다. OpenCode의 도구 대기 취소가 REA 내부 프로세스 종료까지 보장한다는 뜻은 아니다. 제한 도달 시 부작용과 남은 프로세스를 확인한 뒤 복구하며 자동 재실행하지 않는다.

## 확인 범위

Python 문법 확인, 설치 전후 설정 비교, 설치 지침과 원본 일치 확인을 했다. 첫 설치 준비 호출은 import 경로 누락으로 파일 변경 전에 실패했고 tools 경로를 지정한 후 설치를 완료했다. 새 테스트·모델 부하·Rider GUI 조작은 하지 않았다. 지침 변경이 실제 모델의 반복 호출을 얼마나 줄이는지는 아직 재측정하지 않았다. 이번 변경으로 추론 수준을 낮추거나 필수 검증을 강제로 생략하지 않는다.

새 설정·지침은 작업 종료 후 OpenCode 연결을 다시 시작해야 반영된다. 실행 중인 Rider/OpenCode/Strata는 중단하지 않았다. 푸시하지 않았다.
