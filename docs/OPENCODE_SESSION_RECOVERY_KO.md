# OpenCode 장기 작업 세션 복구 설정

Windows와 macOS의 OpenCode에서 장기 코딩 세션이 작업 상태를 다시 확인하고, 명령 실행을 기다리며 멈추거나 도구 호출을 반복하는 문제를 줄이는 opt-in 설정입니다. Strata 서버, 모델, GPU, Rider 프로젝트 파일은 변경하지 않습니다.

저장소 루트에서 실행합니다.

~~~powershell
& "$env:USERPROFILE\Strata\.venv\Scripts\python.exe" tools\configure_opencode_session_recovery.py
~~~

Windows에서 해당 Strata Python 환경을 사용하지 않는 경우 Python 3.10 이상이 설치되어 있으면 py -3 명령으로 실행할 수 있습니다. macOS에서는 다음을 실행합니다.

~~~sh
python3 tools/configure_opencode_session_recovery.py
~~~

다른 OpenCode 설정 파일을 사용하는 경우에는 --config를 지정할 수 있습니다. 격리된 테스트 설정에는 --instructions-dir와 --source-instructions를 함께 지정할 수 있습니다.

## 적용 값

- 자동 context compaction을 켭니다.
- 최근 대화 보존량을 12,000 토큰으로 설정합니다.
- 모델의 context limit 아래 65,536 토큰을 compaction 여유로 둡니다. 262K 모델에서는 세션이 한도에 닿기 전에 요약을 시작합니다.
- Build agent의 최대 단계를 60으로 제한합니다. 제한에 도달하면 OpenCode가 도구를 제거하고 텍스트로 진행 상태를 요약합니다.
- 아래의 한국어 복구 지침 파일을 OpenCode 전역 instructions 목록에 추가합니다.

기존 provider, model, API key, 권한 및 기타 설정은 보존합니다. 실제 config는 저장소에 포함하지 않습니다. 변경 전 설정 백업은 config 파일 옆에 생성됩니다. 같은 도구를 다시 실행하면 이미 적용된 값은 중복 추가하지 않습니다.

## 세션 복구 규칙

재부팅, Rider/OpenCode 재시작, 작업 중단 뒤에는 현재 Git 상태와 diff, 작업 인계 문서, 관련 프로세스를 먼저 확인합니다. 이미 반영된 코드를 다시 구현하지 않고 누락된 확인과 검증만 이어갑니다.

첫 도구 호출 전에 의도를 분류합니다. `질문:` 또는 원인·의미·방법·가능성·비교·추천을 묻는 문장은 설명만 합니다. `작업:`·`실행:`으로 시작하거나 대상·완료 조건이 분명한 수정·테스트·설정 요청만 실제 작업으로 처리합니다. 대상·완료 조건이 없는 `봐줘`, `확인해줘`, `처리해줄래`, `될까` 같은 모호한 표현은 파일·터미널·GUI를 건드리지 않고 “설명만 원하나요, 실제 확인·수정까지 진행할까요?”라고 한 번만 묻습니다. 질문에 물음표가 없거나 이전 작업이 있었다는 사실만으로 실행 권한을 추정하지 않습니다.

진행 중인 코딩 세션에서도 새 메시지가 질문이면 기존 작업을 자동 재개하거나 새 조사를 시작하지 않습니다. 사용자가 `계속`, `작업:`, `실행:` 또는 구체적인 행동을 명시했을 때만 미완료 작업을 이어갑니다.

실제 작업은 `설계 전용`, `문서 전용`, `구현` 중 하나로 먼저 범위를 정합니다. `설계해줘`, `구조를 제안해줘`, `아키텍처를 검토해줘`, `계획을 작성해줘`는 설계 전용입니다. 관련 자료를 읽고 요청한 설계 문서 또는 답변 안의 설계안·영향·후속 단계만 다루며, 소스 코드·테스트·빌드·실행·설정·에셋을 바꾸지 않습니다.

문서 전용 요청은 명시한 문서만 만들거나 고칩니다. 구현은 `구현:`, `코드로 반영해줘`, `기능을 추가해줘`, `버그를 고쳐줘`, `실제 파일을 수정해줘`처럼 코드 변경이 명시됐을 때만 합니다. 설계안, TODO, 인수 기준, 예시 코드는 구현 권한이 아니며, 설계에서 발견한 개선점이나 기능을 요청 범위 밖에서 자동으로 구현하지 않습니다.

`구조를 수정해줘`처럼 설계 문서 수정인지 코드 리팩터링인지 대상·동작·완료 조건만으로 구분할 수 없으면 도구를 호출하지 않습니다. 한국어로 한 번만 “설계 문서만 수정할까요, 코드 구현·리팩터링까지 진행할까요?”라고 물은 뒤 답을 기다립니다.

## 구조·중복 구현 게이트

구현 전에 관련 이름·인터페이스·저장소·manager·service와 기존 테스트를 검색해 기능 소유 모듈을 확인합니다. 같은 기능의 두 번째 구현, 임시 wrapper, 병렬 manager/store/supervisor를 만들지 않습니다. 기존 소유자가 있으면 그 모듈을 확장하고, 새 소유자가 필요한 경우에는 이전 소유자와의 경계와 이유를 먼저 기록합니다.

기능은 한 모듈과 한 공개 진입점이 소유합니다. 새 의존성은 호출 방향을 짧게 확인해 순환 의존성이 생기지 않게 합니다. 한 곳에서만 쓰는 코드를 미리 범용 프레임워크나 플러그인으로 만들지 않습니다. 변경 뒤에는 관련 테스트·빌드·포맷·프로젝트가 제공하는 구조 검사를 실제 실행합니다. 자동 구조 검사가 없다면 미실행으로 기록하고, 완료 보고에 기존 구현 재사용 여부·새 소유 모듈·의존성 영향·중복 미발견 근거를 남깁니다.

UAC 보안 데스크톱은 CUA Driver나 OpenCode 셸이 승인할 수 없습니다. 설치기는 `Start-Process -Verb RunAs`, `runas`, `sudo`, `gsudo` 형태의 shell 도구 호출을 하드 차단합니다. UAC가 보이거나 권한 거부로 관리자 권한이 필요한 경우 에이전트는 `BLOCKED_UAC`와 필요한 단일 관리자 명령·이유를 보고하고 현재 작업을 끝냅니다. 승인 대기, 폴링, 같은 명령 재시도, 권한 우회는 하지 않습니다. 사용자가 관리자 PowerShell에서 실행한 결과를 새 요청으로 제공한 뒤에만 상태를 다시 읽습니다.

작업 수락 조건이 모두 검증되면 완료는 종료 상태입니다. 에이전트는 필요한 CUA session 정리 후 즉시 최종 한국어 답변을 보내며, 추가 조사·도구 호출·후속 작업을 시작하지 않습니다. 오래 걸리는 빌드·테스트는 비대화형 제한 시간과 별도 출력 로그로 실행하고, 서버·워처는 별도로 시작합니다. 작업이 멈춘 것 같으면 새 명령을 시작하기 전에 기존 프로세스와 셸 상태를 확인합니다.

Strata 로그의 done (stop, cancel=False)는 모델 생성 또는 도구 호출 생성이 끝났다는 표시입니다. OpenCode가 도구를 실행하고 결과를 돌려줄 수 있으므로, 이 로그만으로 전체 작업이 끝났다고 판단하거나 같은 요청을 다시 보내지 않습니다. 도구 단계 제한에 도달하면 완료·미완료·검증·다음 행동을 요약합니다.

## 적용 확인과 복구

도구는 JSON을 다시 읽어 파싱하고, config에 변경 전 백업을 남깁니다. OpenCode가 실행 중인 세션은 이미 읽은 설정을 계속 사용할 수 있습니다. 진행 중인 작업을 끊지 말고 안전한 지점에서 OpenCode를 재시작한 다음 새 세션 또는 재개 세션에서 확인합니다.

잘못된 config 형식이면 설치기는 수정을 거부하고 파일을 보존합니다. 복구가 필요하면 출력된 백업 파일을 이용해 이전 config를 복원할 수 있습니다. 자동으로 Strata 서버를 재시작하거나 GPU 작업을 실행하지 않습니다.
