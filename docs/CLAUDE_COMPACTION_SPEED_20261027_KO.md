# Claude Desktop 자동 압축 시간 실측

2026-10-27, 실제 Claude Desktop Code → OpenCodex(10100) → Strata(8080) 경로에서 자동 압축 53.246→29.528초를 관측했다. 압축 요청의 서버 생성 토큰은 5,269→2,652개였다. 압축 후 제약·미검증 상태 회상, 후속 수정과 독립 검사를 통과한 선택형 서버 개선을 현재 PC의 ON 프로필에 적용했다. 동일 입력의 반복 A/B로 일반화한 수치는 아니다.

모델·GPU는 기존 RTX 3090 Ti 단일 구성이며, 모델/자동 압축 창 262,144와 출력 상한 32,000을 유지했다. 일반 작업의 추론 성능을 낮추거나 요약 출력을 강제로 자르지 않았다. 진단 대화의 실제 일반 요청은 High였다.

## 원인과 시험 범위

이전 자동 압축은 53.246초였고 Strata는 요약 요청에서 5,269개 토큰을 생성했다. 캐시를 재사용한 입력 처리보다 긴 요약 생성이 주요 구간이었다. 이 수치는 [이전 Desktop 실측](CLAUDE_DESKTOP_262K_20261027_KO.md)의 기록이며, 디스크 속도나 네트워크 지연만 줄여 해결되는 비용으로 해석하지 않는다.

자료 6,453행 읽기, 두 계산 파일 구현, 같은 대화의 수정, 추가 자료 1,804행 읽기로 자동 압축을 유발했다. 실제 앱의 압축 경계 기록과 서버 생성 로그를 대조하고 별도 AST 기반 검사기로 계산 결과·상수 참조·표식·외부 주석·보호 파일을 확인했다. 자료의 앞·중간·끝에 서로 다른 값과 개정 정보를 넣었다.

`preTokens`는 Claude의 압축 경계 수치, `postTokens`는 앱이 기록한 압축 후 수치다. 실제 API 입력과 시스템·도구·최근 메시지를 포함한 후속 요청 크기는 각각 다르다. 이 시험을 사용자 입력 262,144개와 추가 출력을 동시에 처리한 증거로 사용하지 않는다.

후보 3도 더 느려 최상위 `CLAUDE.md`에 추가한 해당 절만 제거했다. 생성된 공통 지침에 중복 요약 규칙을 덧붙이지 않았다.

## 적용한 변경

`serve/anthropic_compaction.py`가 Claude Code의 알려진 전체 압축 요청만 식별한다. 원래 요약 요청·추가 사용자 지침·도구·메시지·훅 문맥을 모두 보존하고 마지막에 간결한 내부 복구 요약 지침을 추가한다. 기본값은 꺼져 있으며 `anthropic_compact_summary: true`인 서버에서만 사용한다. 일반 작업, 알 수 없는 템플릿, 이미지/도구 결과, 후속 assistant 턴은 변경하지 않는다. 압축 요청이 마지막 `user` 메시지 뒤의 훅 `system` 문맥보다 앞에 있는 실제 Desktop 형태와 여러 텍스트 블록을 지원한다.

내부 복구 설명은 간결한 영어를 기본으로 하되 사용자 제약·정확한 문구는 원문으로 남긴다. 사용자가 압축 언어·서식을 명시하면 해당 요청을 따른다. 사용자에게 보이는 일반 진행·최종 보고는 기존 한국어다. 목표는 1,000~1,800토큰이지만 필수 사실을 남기기 위해 늘릴 수 있다. 요청의 추론 수준과 출력 상한은 그대로이며 별도 요약 모델·에이전트·훅 프로세스를 추가하지 않는다.

`serve/server.py`는 생성과 `/v1/messages/count_tokens`에 같은 변환을 적용해 토큰 계산을 일치시킨다. 기존 렌더링의 대화 앞부분이 그대로 유지되는 CPU 검사도 통과했다. 기본 비활성 상태에서는 원래 요청 객체를 그대로 반환한다.

첫 서버 후보는 합성 요청의 실제 토큰 계산 API에서는 반영됐지만 Desktop 요청 뒤의 훅 `system` 메시지 때문에 감지를 놓쳤다. 이 상태의 수동 압축은 73.692초였고 입력 94,534개를 차가운 캐시에서 처리하는 데 30.964초가 포함됐다. 서식 개선의 적용·효과 증거로 사용하지 않았다. 다중 텍스트 블록과 후행 훅 문맥을 보완한 뒤 실제 자동 압축에서는 두 텍스트 블록·6,977자 요청의 식별 조건이 모두 맞고 적용 로그가 나왔다. 이 요청의 서버 입력은 **229,822개**, 캐시를 쓰는 전처리는 로그상 약 3초였다.

현재 PC는 실행 중인 NVFP4 fork의 `serve/server.py`에 필요한 다섯 위치만 패치하고 같은 폴더에 새 모듈을 배치했다. 서버 루트 파일을 fork에 통째로 덮어쓰지 않았다. 다음 두 현재 PC 파일에만 `anthropic_compact_summary: true`를 저장해 ON 실행기가 프로필을 다시 생성해도 유지한다.

범용 저장소 기본값과 OFF 템플릿은 이 기능을 자동 활성화하지 않는다. 새 PC·별도 fork는 해당 서버 코드가 반영돼야 하며, 이번 시험으로 새 설치나 다른 모델까지 검증했다고 보고하지 않는다. 되돌리려면 현재 PC ON 템플릿과 생성 프로필의 해당 키만 `false`로 바꾸고 기존 supervisor로 유휴 상태에서 재시작한다. 오래된 전체 설정 백업으로 덮어쓰지 않는다.

## 검증

최종 CPU/Mock HTTP 검사는 `python -m unittest serve.test_anthropic_compaction serve.test_anthropic_tool_cache serve.test_anthropic_deferred_tools` **32개 통과**다. 개발 중 같은 묶음이 28→29→30→31→32개로 늘며 통과했고 최종 문구 수정 후 32개를 다시 통과했다. 이 숫자는 고유 최종 검사 수이며 반복 횟수를 합산하지 않았다. 생성·토큰 계산 일치, 기본 경로 보존, 다중 블록·큰 접두 대화·훅 문맥·추가 사용자 지침 보존, 중복 적용 방지, 잘못된/변경된 템플릿 제외, 렌더링 캐시 접두부 보존을 확인했다. CPU 출력 처리율은 GPU 성능 수치로 사용하지 않는다.

실제 Desktop 자동 압축 후에는 개정 자료를 1~902행과 903~1804행으로 끝까지 읽고 최신 할인율 0.20·배송비 9·기준 80을 반영했다. 같은 대화의 후속 요청에서 정답을 다시 알려주지 않고 다음을 회상하게 했다. 네이티브 오프라인 요구, 웹 구현 제외 이유, 계산 여섯 사례 통과, Windows UI/다른 OS 미검증, 실행·예약된 백그라운드 작업 없음, 검증 명령·새 파일·서버/전역 설정 변경·커밋·푸시 금지가 정확히 유지됐다.

후속 수정은 `RETRY_LIMIT`만 3→4로 바꾸고 재읽었다. 외부 검사에서 계산 여섯 사례, 실제 config 상수 참조, 표식 세 개와 외부 주석 두 개, 보호 파일 해시, 예상 밖 파일 없음이 모두 통과했다. 한국어 최종 보고와 Desktop 완료 표시도 확인했다.

최종 모듈 게시 후 실제 `/compact`에 한국어·정확히 세 항목(현재 상태, 제약과 미검증, 다음 행동)을 지정한 호환성 시험도 했다. 요청한 한국어 세 항목과 현재 값·금지·미검증 정보가 유지됐다. 이 수동 압축은 `preTokens=95,695`, `postTokens=6,822`, 57.436초, 서버 입력 96,576개·생성 2,757개였고 차가운 캐시의 전처리 31.481초가 포함됐다. 자동 압축의 따뜻한 캐시 표본과 직접 속도를 비교하지 않는다. 이 수동 요청은 최종 서버의 엄격한 자동 서식 감지에 일치하지 않아 원래 요청을 보존한 기본 경로로 처리됐다. 사용자 지정 압축이 유지되는 호환성 증거로만 사용한다.

최종 운영 모듈과 저장소 모듈의 바이트 일치, 임시 구조 로그와 내부 실험 환경 변수 제거, 후행 훅이 있는 토큰 계산 API의 일치도 확인했다. 유지보수 문서의 오래된 ToolSearch 미지원 설명을 실제 3p 프로필 설정과 검증 결과에 맞췄으며, 해당 생성 문서와 소유 해시 한 항목만 함께 갱신했다. 전체 설정기를 다시 실행하지 않았다.

최종 읽기 전용 응답도 현재 네 값과 미검증 상태를 정확히 답했고 파일은 그대로였다. 이 마지막 턴에는 새 Read 도구 호출이 관측되지 않았으므로 새 파일 읽기 실행의 증거로 세지 않는다. 실제 Read→Edit→Read 검증은 앞선 자동 압축 후 4단계에서 확인했다. 마지막 외부 파일 검사와 `environment_status`는 통과했고 `ready=true`, `desktop_ready=true`, Strata `in_flight=0`였다. 이 활동 값만으로 다른 클라이언트의 전체 대기열 유휴를 단정하지 않는다.

## 증거와 한계

진단 정본은 `C:\Users\luiny\Strata-data\diagnostics\compact-speed-20261027`이다. 첫 후보는 `observations.json`, 두 번째는 `native-observations.json`, 세 번째는 `root-policy/observations.json`, 실제 서버 개선은 `server-hint/observations.json`에 각각 분리했다. 단계별 독립 검사는 각 폴더의 `verification-stage-*.json`에 저장한다. 네이티브 로그가 압축 때 보존 메시지를 재기록하므로 예전 시간의 사건은 새 측정으로 세지 않는다. 실행 파일 해시·읽기 전용 위치 정보와 설정 변경/제거·운영 파일 게시 백업 영수증도 같은 진단 폴더에 있다.

큰 Read가 현재 컨텍스트의 허용량을 넘긴 실패와 크기를 줄인 후속 호출을 보존했다. 후보 2는 개정 자료 1~1,400행을 읽은 뒤 자동 압축했고, 이후 1,401~1,804행만 읽어 완료했다. 완료 도구의 잘못된 선택 인자를 생성했다가 수정한 모델 오류도 있었으므로 모든 도구 인자 오류가 해결됐다고 주장하지 않는다. 중간 설명에 영어가 나온 사례가 있었고 최종 보고는 한국어였다.

임시 요청 구조 진단은 역할·블록 수·문자 수·식별 조건의 참/거짓만 남겼고 원문·헤더·자격증명은 기록하지 않았다. 최종 운영 모듈에서는 이 임시 진단 코드를 제거했다. 기존 supervisor의 버전별 재시작 영수증을 각각 보존했으며 실패한 감지를 숨기거나 같은 재시작 요청을 중복 제출하지 않았다.

Windows UI 빌드, 다른 OS 실행, 임의의 대규모 프로젝트 전체 정보 보존과 모든 미래 버전의 압축 성능은 이 시험으로 검증하지 않았다. Strata의 엔진 인자·모델·GPU·컨텍스트와 OpenCodex 전송 경로는 바꾸지 않았다. 최종 정책은 동일 입력의 반복·짝 비교로 전면 기본값을 바꾸는 수준의 증거가 아니므로 현재 PC에서의 선택 적용으로 한정한다.
