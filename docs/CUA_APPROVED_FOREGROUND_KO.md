# 채팅 안에서 CUA 승인

현재 Rider ACP 연결에서는 별도 Windows 창 대신 `session/request_permission` 선택창을 사용합니다.
- 허용 안 함
- 현재 작업 완료까지 허용

현재 작업의 전경 마우스·키보드 입력 범위와 사용자 PC 사용 방해 가능성을 표시합니다. 완료·취소·연결 종료 뒤에는 승인을 재사용하지 않습니다. 120초 안에 승인하지 않으면 입력하지 않습니다. 지원하지 않는 클라이언트에서는 별도 OS 창으로 자동 전환하지 않습니다.

일반 OpenCode MCP 연결에는 MCP form elicitation으로 채팅 승인을 요청합니다. ACP 작업 경계가 없는 직접 연결은 동작 1회 승인만 지원하며 작업 전체 승인으로 표시하지 않습니다. Rider와 OpenCode의 실제 화면 표시는 아직 직접 검증하지 않았습니다.

# 작업 단위 CUA 전경 입력 승인

기본 입력은 background다. 백그라운드 무동작을 확인했고 전경 입력이 필요하면 `approved_foreground_action`을 사용한다.

## Rider/Hermes ACP

1. 갱신된 ACP 실행기로 OpenCode를 연결한다.
2. 현재 사용자 요청의 첫 전경 입력 때 `CUA 현재 작업 전체 승인` 창이 나타난다.
3. `작업 완료까지 허용`을 누르면 같은 요청 안의 후속 전경 입력은 다시 묻지 않는다. 작업에 필요한 여러 정확한 앱 창을 사용할 수 있으며 사용자 입력·포커스를 방해할 수 있음을 승인창에 표시한다.
4. 완료·오류로 요청이 끝나거나 중지·연결 종료가 발생하면 승인도 끝난다. 다음 요청·다른 채팅에는 승인을 넘기지 않는다.

작업 경계는 ACP 실행기가 실제 session/prompt 요청과 최종 응답·취소로 관리한다. 도구 호출은 OpenCode 세션 메타데이터와 대조한다. 모델이 작업 ID를 인자로 제시하거나 승인을 연장하지 않는다. 중첩된 동일 세션 요청처럼 소유자를 확정할 수 없으면 입력하지 않는다. 하위 분석 결과를 받은 뒤 GUI 입력은 승인된 부모 요청에서 수행한다.

작업 수명 정보가 없는 일반 MCP 연결은 동작1회 승인으로 동작한다. Linux 전경 입력은 차단한다. Windows/macOS 확인창 구현을 포함하지만 이번 작업 단위 승인의 실제 macOS 실행은 미검증이다.

## 유지하는 입력 검증

- 매 동작의 정확한 PID/창 ID와 새 화면을 확인한다. 새 창도 관찰 없이 조작하지 않는다.
- 승인창 대기는60초다. 거절·대기 만료·작업 취소에는 실행하지 않는다. 늦은 응답으로 끝난 작업의 승인을 되살리지 않는다.
- 창 위치·크기와 대상 픽셀을 비교한다. 포커스 색상·애니메이션 때문에 차단될 수 있으며 모든 앱의 컨트롤 초점을 자동으로 증명하는 것은 아니다.
- 문자 입력은 전달 예산 동안 소유 프로세스를 유지한다. 전송 글자 수를 입력 완료로 해석하지 않고 전체 문장을 확인한 뒤 제출한다.
- UAC/보안 데스크톱·데스크톱 전체 입력·셸 입력 우회에는 적용하지 않는다. 이미 전달된 입력은 취소해도 되돌아가지 않을 수 있어 실제 상태를 확인한다.
- 일반 입력 도구와 background Rego는 그대로다. 승인된 전경 입력은 별도 정책의 CUA 프로세스로 처리한다.
