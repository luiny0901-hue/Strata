# 장시간 무인 작업 점검 (2026-10-22)

**상태: PARTIAL.** 실제 장시간 GPU 작업은 하지 않았다. 로컬 모의 장애 검사와 설치된
OpenCode v2.0.22의 격리 ACP 검사를 수행했다. 아래 조기 취소 문제가 남아 모든 시점의
완전 무인 운용·모델 중지·작업 완료를 보증하지 않는다.

후속 실제 경과 시간 검사와 로그/상태 조회 수정은 [지속 검사 결과](AUTONOMY_SOAK_20261022_KO.md)에 기록했다. 아래 조기 취소 실패 이력과 실제 GPU 미검증 경계는 유지한다.

동일 OpenCode 세션의 연속 50회 검사 두 번과 완료 상태 저장·실패 표시 수정은 [2026-10-23 결과](AUTONOMY_CONTINUOUS_20261023_KO.md)에 기록했다.

## 수정한 문제

- CUA 드라이버 요청이 응답 없이 남는 경로: 초기화 20초, 전달 요청 120초 기한을 추가했다.
- 요청 중 드라이버가 정상 코드 0으로 종료해도 오류를 반환한다. 미결 요청은 최대 128개다.
- 응답 완료·실패·부모 EOF에서 타이머·요청 ID·화면 입력 대기 상태를 정리한다.
- 부모가 연결을 닫은 뒤 드라이버가 종료하지 않으면 3초 후 소유 자식만 종료한다.
- 기한 종료 이후 늦은 성공 응답을 전달하지 않으며 입력은 자동 재실행하지 않는다.
- 초기화·재설치·외부 PC 설정에서도 새 수명 관리 모듈을 함께 설치하도록 수정했다.

이 PC의 설치된 프록시가 이전 배포 소스와 같음을 확인하고 백업 후 새 모듈·프록시를 적용했다.
진행 작업을 마친 뒤 OpenCode/ACP 새 세션에서 활성화한다. 외부 PC는 새 소스로 setup을 재실행한다.
변경은 아직 미커밋·미푸시 상태다.

## 검사 결과

- Python 묶음 최종 Ran 78: 77개 통과, Linux 전용 클래스 1개 건너뜀.
  첫 시도에서는 새 모듈이 빠진 설치기 테스트 fixture 때문에 6개 오류가 났으며 fixture를 보완했다.
- JavaScript 48개 및 ACP guard 스크립트 검사 통과.
- 새 lifecycle 단위 검사는 가상 타이머로 1만 건 완료 뒤 남은 요청·타이머가 없음을 확인했다.
  실제 1만 번의 GUI 조작이나 장시간 경과 시험은 아니다.
- 실제 Node 프록시 + 가짜 드라이버 검사: 무응답 기한, 요청 중 종료, EOF 뒤 종료 거부를 확인했다.
  요청은 각 1번만 전달되며 종료 뒤 소유 드라이버 PID가 사라졌다. 시간 초과 fixture만 40ms로
  줄였으며 실제 배포 기한은 120초다. 실제 CUA 드라이버·GUI를 조작하지 않았다.

## 남은 운용 경계

조기 취소 문제의 근본 원인은 아직 확정하지 못했다. UI의 취소 표시만 보고 서버가 멈췄다고
판단하면 안 된다. 실제 모델 서버의 요청·활동 상태 확인이 추가로 필요하다.
UAC·인증·백그라운드 입력 미지원 앱·설치 실패·단계 예산 소진 등은 자동 성공으로 처리하지 않는다.
수락 조건을 충족한 작업은 종료하며 새 요청 없이 계속 작업하는 상시 자동 재개는 활성화하지 않는다.
실제 Windows/Mac/Linux·Rider/Hermes·원격 모델·긴 컨텍스트와 장시간 부하 검사는 수행하지 않았다.
