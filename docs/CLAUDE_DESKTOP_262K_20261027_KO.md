# Claude Desktop Code 262K 작업·후속 수정 실측

2026-10-27, 이 PC의 실제 Claude Desktop Code 화면에서 요청을 보내고 OpenCodex(10100) → Strata(8080)로 처리했다. CLI 직접 생성으로 Desktop 검증을 대신하지 않았다. 준비 입력의 불필요한 도구 정의를 줄이는 설정을 적용했고, 긴 자료 읽기·수정·자동 압축·외부 변경 보존·도구 검색·중지 후 새 수정 요청을 확인했다.

## 환경과 범위

- Windows, Claude Desktop 3.6556.2.0, 내장 Claude Code 2.1.308, 시험 세션 추론 `High`.
- 모델 연산 프로세스 PID 6760은 RTX 3090 Ti에 있었다. RTX 3090은 표시용 앱이 사용했다. Unity Editor가 열린 기존 환경을 유지했으며 엔진 프로젝트를 조작하거나 게임 제작 검증을 하지는 않았다.
- 모델 창과 자동 압축 창은 모두 **262,144**, 출력 상한은 32,000이다. 이 창에는 시스템·도구·대화·출력 여유가 함께 들어간다. 262,144개 사용자 입력 토큰을 꽉 채우는 시험은 아니다.
- 시험 폴더는 저장소의 무시된 `.strata-mcp/desktop-262k-20261027`이다. 변경 허용 파일은 `config.py`, `calculator.py` 둘뿐이다. 자료·768개 방해 파일·한글 UTF-8 BOM/CRLF 파일 등을 포함한 **보호 파일 772개**의 SHA-256을 독립 검사했다.
- 새 모델·런타임 설치, 모델 재포장, Strata 재시작, GPU 전력·메모리 설정 변경은 하지 않았다. 사용자 MCP와 OpenCodex 설정, ON/OFF 원본 프로필의 시작 전후 해시가 같았다. Desktop만 정상 종료 후 다시 열었다.

## 확인한 병목과 변경

### Desktop 게이트웨이의 도구 정의 선행 로딩

적용된 Desktop 3p 프로필에 `toolSearchEnabled`가 없었다. 사용자 Claude 설정에는 `ENABLE_TOOL_SEARCH=true`가 있었지만 새 Desktop 세션은 많은 도구 정의를 먼저 전송했다. [공식 Desktop 게이트웨이 문서](https://claude.com/docs/third-party/claude-desktop/gateway#mcp-tool-search)는 Desktop의 별도 설정이 필요하다고 설명한다.

적용된 `configLibrary/57dfacd4-1c7c-4c8f-b9e0-ab6d2f229ab6.json`의 해당 키만 `true`로 추가했다. 기존 공급자·모델·인증값을 유지했고, 원본은 로컬 비공개 백업으로 보존했다. 앱 재시작 뒤 같은 저장소의 새 세션에서 측정했다.

| 관측 | 변경 전 | 변경 후 |
|---|---:|---:|
| 작은 준비 파일을 읽은 뒤 실제 API 전체 입력 | 69,590 | 38,619 |
| Desktop 표시 MCP 정의 | 약 35.5K | 약 6.3K |
| Desktop 표시 시스템 도구 | 약 17.2K | 약 9.6K |
| 별도로 표시된 지연 MCP 정의 | 없음 | 약 29.2K |

준비 작업의 전체 입력은 **44.505% 감소**했다. 같은 폴더·같은 보호 범위 조회를 사용했지만 프롬프트 표현과 출력 길이가 완전히 같은 반복 A/B는 아니다. 이 비율은 해당 입력 비용의 차이이며 모든 작업의 완료 시간 개선율이 아니다. 도구를 삭제한 결과도 아니다. 실제 `ToolSearch` 1회 뒤 `strata-maintenance.environment_status` 1회가 성공했다. Read·Edit·완료 도구도 계속 동작했다.

`tools/claude_opencodex_client.py`의 진단 결과에는 이제 `desktop.tool_search`가 나온다. 프로필의 누락·false·true와 `runtime_status=not_verified`를 구분한다. 저장 설정만 검사하는 `doctor`가 런타임 성공으로 표시하지 않게 유지했다. 이 보고서의 실제 세션 증거는 별개다. 새 PC 설정 문서에도 Desktop 프로필 키와 재시작 후 호출 확인 절차를 추가했다.

### 읽기 오류 재시도와 완료 도구의 불필요한 선택지

변경 전 긴 파일 읽기는 남은 컨텍스트 한도 오류를 세 번 반환했다. 서로 다른 도구 호출 ID 기준이며, 압축 보존 과정에서 중복 기록된 동일 결과는 한 번만 셌다. 이 중 같은 파일·범위를 그대로 반복한 호출이 있었다. 이후 자료 전체를 연속 구간으로 읽고 작업을 완료했다.

생성 지침과 현재 사용자가 편집한 `~/.claude/CLAUDE.md`의 해당 문장만 보완했다. 같은 인자의 한도 오류를 반복하지 않고, 반환된 범위와 허용량에 맞춰 미확인 구간만 읽도록 했다. 전역 지침 전체나 사용자 소유권 해시를 다시 생성하지 않았다.

개선 후 첫 완료 보고에서는 앱의 `wrap_up`에 존재하지 않는 `actions.action="reply"`를 만들어 스키마 오류가 한 번 발생했다. 같은 턴 안에서 유효한 호출로 고쳐 완료했다. 추가 선택이 필요 없으면 recap만 전달하고 선택이 필요할 때 실제 스키마를 쓰도록 기존 완료 지침을 보완했다. 마지막 수정 턴의 완료 도구는 recap만 사용해 한 번에 성공했다. 지침은 모델의 모든 잘못된 인자 생성을 강제로 차단하는 장치는 아니다.

## 남은 범위

이 PC의 Windows·3090 Ti·현재 모델·두 새 Desktop 세션에서 확인했다. macOS·Linux·외부 PC/네트워크·24시간 연속 실행·실제 대규모 게임/프로그램 빌드는 시험하지 않았다. 코드 검사는 작은 격리 프로젝트의 동작·보존 계약이며 상용 프로젝트 완성도 검증이 아니다.

큰 입력의 전처리와 약 53초 자동 압축 비용은 남는다. 출력·압축 여유를 제거하거나 262K 설정을 줄여 겉보기로 회피하지 않았다. 압축 후 중간 진행 문장이 한 번 영어로 나온 반면 최종 보고는 한국어였다. 모든 상황의 한국어 일관성과 임의 도구 인자 생성까지 해결했다고 보지 않는다.

기존 사용자 변경·삭제·미추적 파일이 많은 작업 트리는 보존했다. 이번 요청으로 커밋·푸시는 하지 않았다.
