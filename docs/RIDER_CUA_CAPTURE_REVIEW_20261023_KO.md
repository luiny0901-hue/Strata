# Rider CUA 화면 재확인 개선

## 확인한 코드 경로
- 백그라운드 CUA는 상주 프로세스를 재사용한다.
- 전경 CUA는 승인된 도구와 정확한 창으로 정책을 한정한 별도 프로세스를 동작마다 생성하고, 클릭 직전에 새 화면과 좌표 주변 픽셀 및 창 경계를 비교한다.
- 이전 구현은 재확인 이미지를 항상 max_image_dimension=1920으로 요청했다. 처음 이미지를 다른 크기로 요청했다면 같은 창도 비교 조건이 맞지 않아 거부되거나 잘못된 영역을 비교할 수 있다.

## 변경
- 최초 프레임의 width/height 중 큰 값을 재확인 이미지 크기 제한으로 사용한다.
- 프레임 크기가 없거나 잘못됐으면 입력 전에 중단한다.
- 승인, 창 경계 확인, 픽셀 비교, 입력 뒤 확인 규칙은 유지한다.

## 남은 비용과 한계
- 전경 동작마다 프로세스 시작 및 스크린샷 획득 비용이 있다. 재사용은 정책과 작업 취소 수명 관리를 바꾸므로 이번 변경에 포함하지 않았다.
- Rider 프로세스가 실행 중임을 확인했다. 실제 Rider 클릭, 입력 및 자동 테스트를 실행하지 않았으므로 지연 감소나 정확도 향상 수치를 주장하지 않는다.
- 새 OpenCode 연결부터 로컬 설치 변경이 적용된다.


## 후속 테스트: 커서·클릭 좌표
- 기존 Node 테스트 15/15 통과 후, 2개 회귀 테스트를 추가해 17/17 통과했다.
- 추가 조건: 1280/1536 축소 이미지, 세로 화면, 소수 배율, 양수·음수 모니터 원점, 모서리·중앙 좌표. 계산된 AI 오버레이 위치와 클릭 이미지 좌표가 동일한 변환 기준임을 확인했다.
- 전경 재확인 크기 선택을 함수로 분리하고 잘못된 값 및 지원 범위 초과를 입력 전에 거부했다.
- 실행 명령: node --test tools/cua-driver/opencode-grounding.test.mjs tools/cua-driver/opencode-foreground.test.mjs
- 실제 Rider HWND 22546384의 agent-perf-fixture 펼침 삼각형을 최신 스크린샷의 (71,233)에서 2회 클릭했다. 펼침→접힘을 스크린샷으로 확인했다. 파일 내용은 편집하지 않았다.
- 실제 클릭은 Codex computer-use의 @oai/sky 경로다. 설치된 OpenCode cua-driver의 AI 커서 표시 및 배경 클릭 경로의 실측 증거가 아니다. 4K/8K·혼합 DPI는 합성 회귀 테스트이며 실제 다중 모니터 시험으로 표시하지 않는다.
