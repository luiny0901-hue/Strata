# 실행 중 개발·유지보수

운영 설정을 사용하는 OpenCode로 이 저장소를 개발할 수 있다. 소스 수정과 운영 반영을 구분한다.

1. 소스와 관련 검사만 먼저 수정한다. 운영 세션을 테스트 대상으로 삼거나 실행 중인 서버·모델·CUA를 종료하지 않는다. 복구 시험은 별도 설정·DB·출력 폴더와 모의 서버를 쓴다.
2. ACP/output 플러그인은 내용 해시별 versions 디렉터리에 모든 자산을 준비한 뒤 설정 참조를 전환한다. ACP의 bootstrap/preflight도 같은 버전에 고정한다. 이전 버전 파일은 삭제하거나 덮어쓰지 않는다. 해당 버전 파일이 외부에서 바뀌었으면 덮어쓰지 않고 설치를 거부한다.
3. 설치기는 설정 백업을 남긴다. 이미 실행 중인 OpenCode의 설정 감시·재로딩 시점은 클라이언트에 따라 다르므로, 진행 중 작업을 끝낸 뒤 연결 프로세스를 재시작하고 새 작업으로 확인한다. 즉시 무중단 적용·롤백을 보장하지 않는다.
4. 전역 지침, scripts의 직접 실행기, CUA 및 REA 설치 자체는 이 버전 고정 대상이 아니다. 해당 파일의 운영 업데이트는 현재 작업이 끝난 뒤 수행한다. 실행 중 CUA 바이너리 교체나 모델/서버 재시작을 임의로 수행하지 않는다.
5. 문제 발생 시 백업 설정으로 참조를 복구할 수 있도록 이전 버전을 보존한다. 활성 프로세스가 쓰는 버전을 모르는 상태에서 자동 정리하지 않는다. 외부 클라이언트 재설치는 같은 버전별 자산 준비 경로를 사용한다.

검증: `python -m unittest tools.test_opencode_runtime_assets tools.test_remote_agent_client`.
CPU 격리 검사이며 실제 Rider/Hermes 작업 중 hot reload나 외부 macOS 실행을 검증한 결과가 아니다.
